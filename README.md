## 覆盖已有部署

把新包上传到 NAS 的 `/vol1/1000/测试`，执行：

```bash
cd "/vol1/1000/测试" &&
unzip -oq "StrimKeep-v0.6.4-composefix.zip" -d "StrimKeep-v0.6.4-composefix" &&
bash "/path/to/StrimKeep-v0.6.4-composefix/StrimKeep/update.sh" "/path/to/StrimKeep"
```

更新脚本先解析现有 Compose，把已有账号配置、端口和挂载路径转成直写 YAML，保留数据库、加密密钥、播放 Token、`data` 和 `strm`。旧 `.env` 文件保留，但新 YAML 不依赖它。不要先删除旧项目。完成后刷新网页确认版本 `0.6.4`。

旧本地目录 `StrimKeep媒体库` 自动更名为 `影视媒体库`，并同步修改本地路径记录；不会改 115 云盘目录。**Emby 若选的是旧子目录，更新后请改成 `/strimkeep/影视媒体库/电影`、`/strimkeep/影视媒体库/剧集` 等实际路径。**若新旧目录同时存在，不合并或覆盖两边内容，日志会提示。

新转存直接保存到所选目录，不添加 `转存任务-N`。成功整理后清理相关空文件夹；仍有未识别视频、字幕或其他内容的目录保留。旧任务目录不会被不加判断地整批删除。

日常整理无需预建归档索引。未识别目录留空时失败文件原位保留；配置后保留资源原目录层级和附属文件，整体移入未识别目录；先完成同批可识别文件，再转移剩余目录。目录同名时原位保留，不合并、不改名。来源根目录里的散装视频保留原名与关联字幕直接转入。播放使用独立取链通道，后台处理不等播放结束。

## STRM 与 Emby

新安装默认使用项目下 `data` 和 `strm`，程序容器内为 `/data`、`/strm`。覆盖更新沿用原来的路径。

在 **Emby 服务的 `volumes` 下**加入：

```yaml
- "/path/to/StrimKeep/strm:/strimkeep:ro"
```

保存并重新创建 Emby 容器，媒体库选择 `/strimkeep` 下的实际分类目录。保留  原有的 `/strm` 挂载。StrimKeep 的 Emby 路径映射默认是 `/strm` → `/strimkeep`；如果实际挂载不同，在网页修改映射。

全量同步按所选云盘目录的实际内容生成和更新：改名、移动和播放地址改变都会更新相关 STRM。默认清理所选本地同步范围内没有对应源文件的 `.strm`，包括同一输出范围的遗留 STRM；保留 NFO、海报等非 STRM 文件。目录读取不完整时不执行失效清理。

## 通知和定时

TG 通知可分别开关：入库海报、转存结果、STRM 汇总、STRM 文件明细、失败与登录异常、Emby 检查、普通任务结束消息。无资源的定时轮询只写实时日志，不发送 TG。文件明细、普通结束消息和 Emby 检查默认关闭。

定时整理与定时同步均支持间隔和五段 Cron；默认北京时间。例：`0 3 * * *` 为每天 03:00。定时同步目录单独保存。整理联动延迟支持 `1.5` 秒；已有配置保持原值。

## 新安装与开发

进入包含 `docker-compose.yml` 的项目目录，在 YAML 的 `ADMIN_PASSWORD` 填写至少 12 位密码，必要时修改 `ADMIN_USERNAME`，然后执行 `bash start.sh`。账号密码只在首次创建数据库时生效；已有登录账号保留。默认挂载 `./data:/data` 和 `./strm:/strm`；更换宿主机目录直接修改挂载左侧，容器右侧保持 `/data`、`/strm`。无需 `.env` 或输入路径变量。端口默认 9000。Docker 内置 Python、依赖和 FFprobe，NAS 无需另外安装 Node 或 Python 包。

前端 Vue 3、TypeScript、Element Plus、Vite；后端 Python 3.12、FastAPI、SQLite、p115client、FFprobe；Cron 使用 croniter。精确依赖见 `backend/requirements.lock` 和 `frontend/package-lock.json`。

前端由 Dockerfile 的 `node:22-alpine` 阶段编译，宿主机不需要 Node；改完 `frontend/src` 直接 `docker compose up -d --build` 即可生效，首次构建需要访问 npm registry，可用 `--build-arg NPM_REGISTRY=https://registry.npmmirror.com` 换成国内镜像。仓库里遗留的 `frontend/dist` 不再参与镜像构建。

后端回归 409 项（含 0.6.5 新增 5 项）在 NAS 的容器内跑通；镜像重建与 0.6.5 影子实例的接口、静态缓存、限流验证也在同一台飞牛上完成。真实 115 转存与 Emby 入库仍以现场任务为准。
