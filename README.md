**StrimKeep｜面向 302 STRM + Emby 的影视库管理与智能治理工具**

> **一套面板，管理两套 STRM 影视库。** 对比本地库与分享库的画质和完整性，找出重复版本、残缺剧集与缺集情况；先生成治理计划，确认后再执行清理。

StrimKeep 是一款面向 **飞牛 OS / Linux NAS + 302 STRM + Emby** 的影视库治理工具，重点面向使用 **115 网盘、123 云盘、光鸭云盘** 维护个人影视库的用户。不仅管理双库的质量和去留，还提供 **媒体总览、片库映射、影视探索、追更订阅、近 24 小时入库汇报、晨报与 Telegram Bot**。

**StrimKeep 是 302 STRM 影视库的下游治理工具，不生成 STRM，也不接管 Emby 播放。** 无论 STRM 由哪款工具生成，它直接扫描 NAS 上已存在的本地库与分享库，从 **STRM 文件名、影视目录名、相对路径及季集目录**中提取标题、年份、季集号和画质标签，进行双库匹配、去重与质量对比。

对于需要腾出网盘空间的本地库，StrimKeep 还可以将 STRM 的**相对目录与文件名**映射到 NAS 上已挂载的真实视频源目录，匹配可靠且确认执行后联动清理。它不依赖 115 专属删除 API，主要适用于 **115、123、光鸭** 等具有相应挂载能力的场景；**302 播放地址本身不能作为删除源文件的依据**。

> [!CAUTION]
> **重要：本项目会真正删除文件。** 主动确认清理本地库后，可能连同 NAS STRM 与挂载的网盘源文件一起删除；删除可能同步到远端云盘，无法保证可以恢复。第一次使用务必先扫描、核对清单与路径，再决定是否执行。

## 项目定位

很多玩 **302 STRM + Emby** 的 NAS 用户会同时维护两套媒体库：

- **本地库**：STRM 代表个人媒体源的版本，源文件通常位于自己有管理权的网盘目录。
- **分享库**：来自分享目录或其他来源的 STRM，作为另一份媒体版本参与对照；本项目清理分享库时仅处理 NAS 侧的 STRM 及关联附属文件。

当两库出现同一部电影、同一季剧集的不同版本时，StrimKeep 会结合文件名信息、剧集完整性和用户设定的规则，**给出保留与清理建议**。它不会因为扫描出了建议就自动删除；正常流程为：

**扫描双库 → 对照与决策 → 生成可预览计划 → 人工确认 → 安全复核 → 执行与记录。**

它定位在 **STRM 生成 / 302 播放之后的治理环节**，不是 302 链接生成器，也不替代 Emby 播放器。借助 Emby 与 TMDB，它还能提供媒体库映射、集数进度、影视探索和追更提醒。

## 302 STRM 与双库治理

**STRM 负责播放，StrimKeep 负责治理。** STRM 与 302 播放功能由现有工具及 Emby 提供；StrimKeep 不需要参与上游资源抓取、STRM 生成或 302 跳转。它只需读取飞牛 OS / Linux NAS 上**已经生成的两套 STRM 目录**，就可以开展双库扫描、画质比较和治理预览。

### StrimKeep 怎样识别和对照影视？

1. **扫描 STRM 文件**：分别读取 `/media/local`（本地库）和 `/media/share`（分享库）的 `.strm` 文件及其目录结构，而不是依赖 STRM 内的 302 URL 进行画质判断。
2. **提取媒体信息**：从影视目录名及文件名识别剧名、年份、TMDB 目录标记（如有）、季号、集号和分辨率、动态范围、音频等标签。默认以**规范化剧名 + 年份**进行治理配对，也可在 Web 选择 TMDB 优先策略。
3. **建立双库对照**：根据季集完整性、文件名中的七维画质信息、多季合集保护、白名单和入库静默期等规则，判断哪些版本应保留、哪些需要进一步清理。
4. **预览后执行**：先生成可审查的治理计划；用户确认后再按计划复核实际路径及文件状态，并执行符合安全条件的删除。

### STRM 清理与网盘源文件联动

StrimKeep **通过 NAS 可访问的文件系统路径清理文件**，并非向 302 URL 发送删除请求。

- **分享 STRM 库**：只删除 NAS 侧对应的 STRM 和已识别的附属文件，**不联动删除分享来源的真实视频**。
- **本地 STRM 库**：除了本地 STRM 目录，还需挂载一份与之对应的**真实视频源目录**。程序根据 STRM 的相对路径和文件名，寻找对应的 `.mkv`、`.mp4` 等源文件。只有满足可靠匹配、挂载具备删除能力且人工确认时，才优先清理源文件；源文件删除成功后再清理 STRM。
- **安全兜底**：源文件不存在、路径无法可靠对应、出现多个候选、只能靠“目录中唯一视频”猜测，或删除失败 / 超时，都应保留对应 STRM 并记录原因。

```text
已有的 STRM / 302 播放工具 ──→ NAS 的本地 STRM 库 ──┐
                                                ├─→ StrimKeep 扫描 / 配对 / 七维对比
已有的 STRM / 302 播放工具 ──→ NAS 的分享 STRM 库 ──┘              │
                                                                  ↓
                                                           预览治理计划
                                                                  ↓
                                                            用户确认执行
                                                              ↙       ↘
                                      分享库：只删 NAS STRM   本地库：先匹配真实源文件
                                                                       ↓
                                      可写的网盘文件系统挂载 ──→ 删源成功后再删 STRM
```

### 重点适用网盘：115 / 123 / 光鸭

| 网盘 | 适用方式 |
| --- | --- |
| **115 网盘** | 已有 302 STRM + Emby 影视库；如果真实源文件经 CD2 等工具可写挂载到 NAS，可按路径执行源文件联动清理 |
| **123 云盘** | 同样可以将现有 STRM 纳入双库治理；源文件联动删除取决于所用挂载工具对 123 的支持与实际删除权限 |
| **光鸭云盘** | 同样适用于已有 STRM 的扫描与对照；源文件联动删除须先验证对应挂载驱动、路径映射与删除能力 |

上游可以使用 **CloudDrive2（CD2）、OpenList** 或其他 STRM / 302 相关工具，但它们在本项目中承担的作用不同：**302 / STRM 工具提供播放链路；真正的源文件联动删除必须有 NAS 可访问、可删除的文件系统挂载路径。** 只有 OpenList 页面或 302 链接，并不自动等于具备该路径。

**目录对应示例**（本地 STRM 与源文件位于不同根目录，但相对层级对应）：

```text
本地 STRM：
/media/local/剧集/示例剧/Season 1/示例剧.S01E01.2160p.strm

挂载的真实视频：
/media/cloud/剧集/示例剧/Season 1/示例剧.S01E01.2160p.mkv

分享 STRM：
/media/share/剧集/示例剧/Season 1/示例剧.S01E01.1080p.strm
```

无论使用 115、123 还是光鸭，治理对照读取的都是**两套 STRM 目录本身**。第三条 `/media/cloud` 是用于本地库源文件联动清理的可写目录；它与 302 播放地址是两回事。

## 核心功能

StrimKeep 不接管播放，也不负责从网盘下载影视资源。它负责你已经拥有的 STRM 媒体库的**整理、对照、清理与追更**。

| 模块 | 能做什么 |
| --- | --- |
| **媒体总览** | 影院风格横幅、双库统计、完整度、本周热门电影/剧集、近期治理、分类与服务状态 |
| **双库治理** | 电影与剧集配对、七维画质对照、完整性判断、去重、待删清单与人工确认 |
| **片库映射** | 关联 Emby，显示两库电影 / 剧集、逐季入库数量、缺集进度及媒体详情 |
| **影视探索** | 浏览 / 搜索 TMDB 内容，按地区、类型、年份筛选，显示入库状态并订阅追更 |
| **追更订阅** | 检查剧集更新、管理订阅及提醒，结合媒体库状态追踪新集 |
| **目录清理** | 预览后清理允许范围内的空目录和已知附属文件残留 |
| **入库与晨报** | 近 24 小时入库记录、周期扫描、统计晨报及 Telegram 推送 |
| **日志与计划存档** | 查看实时任务日志、治理计划、实际清理记录和失败原因 |
| **规则设置** | 画质优先级、双库配对、白名单、特别篇、多季保护、静默期、服务连接等 |

### 七维画质与治理策略

核心治理依据是 **STRM 文件名解析出的媒体规格**，不是隐藏评分，也不会把文件大小误当作画质。按启用维度自上而下比较：某一维度区分出高下时立即决策；相同或都无法识别时进入下一维。各项可启用 / 关闭、调整顺序和档位优先级。

| 默认顺序 | 比较维度 | 默认 | 部分档位示例（由高到低） |
| --- | --- | --- | --- |
| 1 | 发布组 | **关闭** | 按用户维护的发布组优先列表比较 |
| 2 | 资源类型 | **关闭** | UHD Remux → Remux → UHD BluRay → BluRay → WEB-DL → WEBRip → HDTV → DVD |
| 3 | 分辨率 | 开启 | 8K → 4K → 2K → 1080p → 720p → SD |
| 4 | 动态范围 | 开启 | Dolby Vision → HDR10+ → HDR Vivid → HDR10 → HDR / HLG → SDR |
| 5 | 帧率 | 开启 | 60 → 50 → 30 → 25 → 24 fps |
| 6 | 色深 | 开启 | 12bit → 10bit → 8bit |
| 7 | 音频规格 | 开启 | TrueHD Atmos / DTS:X → TrueHD / DTS-HD MA → LPCM / FLAC → DD+ Atmos 等 |

**前两项默认关闭。** 例如新部署默认会先比较分辨率，因此 4K WEB-DL 可能优先于 1080p BluRay；如果用户启用资源类型且保持其排序靠前，就会先按片源类型判断。升级时**保留已保存的自定义规则**；「恢复默认」才重新使用默认开关与顺序。规则变更会影响后续删除判断，旧计划须重新扫描。

### 剧集完整性与多季保护

- **缺集独立判断**：本地和分享库分别判断季内是否缺少 E01 或中间剧集，不跨两库拼成“完整季”。
- **逐集画质择优**：双方完整且剧集对齐后逐集比较，按分享版达标比例决定去留（默认阈值 90%，可在 Web 调整）。
- **多季合集保护**：季集合相同可整体择优；一方拥有更多季时，保护合集结构；双方季集合部分重叠时，对重叠季优先保留，避免掏空季集。
- **特别篇 S00**：可选择参与画质治理、忽略或清理；参与多季保护时按季集合规则处理。
- **配对方式**：默认剧名与年份配对，也可启用 TMDB 优先匹配；遇到标识冲突或识别不足时不应进入危险删除。
- **新入库保护**：默认 15 分钟静默期，目录仍在变动的媒体先跳过治理；支持白名单 / 关键词豁免。

#### 两个直观示例

**示例 A：分享库的版本更好且完整。** 本地库是 1080p 完整 10 集，分享库是 2160p HDR 完整 10 集。按启用的画质规则判断分享版胜出后，生成待清理本地副本的计划。**只有人工确认、挂载源文件高置信度匹配且删除成功后，才继续清理本地 STRM**；保留分享版。

**示例 B：分享库虽然清晰却断集。** 本地库 1080p E01–E10 完整，分享库 4K 缺 E05。若命中残缺季治理规则，会建议淘汰残缺分享副本，不因分辨率高就默认保留缺集版本。具体清单以实际匹配、豁免及规则为准。

### Web 功能说明

**媒体库**

- **媒体总览**：影院风格横幅、双库 STRM 数量、电影与剧集数量、完整度、本周热门电影/剧集、近期治理、近 24 小时入库与订阅概况；支持分类切换、桌面/手机及深浅主题。进入页面优先显示缓存，不反复重扫；总览与统计持久化到 SQLite，沿用 5 分钟缓存时效，后台到期更新。点击「刷新总览」清除派生缓存并立即启动更新，完成后页面自动显示最新统计和 Emby 片库事实，无需再点「重建缓存」。配置、订阅、手动完结标记和 TMDB 对照元数据保留；TMDB 对照仍沿用单独的对照任务与设置周期，更新时间在完整度区域显示。
- **片库映射**：关联 Emby 媒体库；展示海报、电影与剧集、各季入库数量、缺集状态、双库逐季对照；手动删除会先试算并要求确认。
- **影视探索**：基于 TMDB 搜索 / 浏览电影和剧集，按地区、类型、年份等筛选，海报显示「已完整、连载中 X/Y、未入库」等信息，可直接发起追更订阅。

**治理与追更**

- **双库治理**：扫描、查看决策依据、按待删/保护/豁免筛选，生成计划并人工确认执行。
- **目录清理**：按指定库或路径预览空目录、已知附属文件残留，再确认清理，不会把未知文件目录当作垃圾随意删除。
- **追更订阅**：订阅新剧、检查更新、暂停或删除订阅；结合 TMDB 与实际媒体库集数判断更新状态。
- **入库与晨报**：近期入库列表、手动扫描、可配置晨报内容和 Telegram 推送。

**运行与设置**

- **规则设置**：七维比较、完整性 / 多季 / S00 策略、匹配方式、白名单、静默期、后台检查计划。
- **服务连接**：Emby、TMDB、Telegram 等参数集中在 Web 配置；无透明代理时可设置 HTTP 代理（支持可选账户密码，目前不支持 SOCKS5），供 TMDB 和 Telegram 等外部请求使用；Emby 不走该项代理。
- **日志中心与计划存档**：实时查看运行过程、历史治理计划及删除结果，便于追查失败原因。

Web 页面支持电脑和手机，侧栏、内容面板、设置和弹窗采用统一的磨砂玻璃表面；浅色为晴空浮城背景，深色为夜景背景，支持主题切换与跟随系统；后端采用单容器运行模式，不要求单独部署前端服务器。

### Telegram Bot

配置 Bot Token、Chat ID 和允许用户后，可以查看状态、运行扫描、收取入库通知与晨报。常用命令包括：

| 命令 | 作用 |
| --- | --- |
| `/status`、`/stats` | 服务状态与片库统计 |
| `/check` | 运行治理扫描，生成计划 |
| `/clean` | **执行治理清理**（会真正删文件） |
| `/ingest`、`/played` | 最近入库与播放情况 |
| `/gap`、`/emby` | 缺集与 Emby 信息 |
| `/sub`、`/sub check` | 订阅与立即检查 |
| `/morning` | 发送晨报 |
| `/search 关键词` | 搜索影视条目 |
| `/logs`、`/help` | 日志和帮助 |

`/clean` 属于危险操作，必须限制机器人使用者；定时巡检只扫描 / 通知，不自动执行删除。

## Docker Compose 部署

适用于飞牛 OS、Linux NAS 和其他 Docker 主机。直接使用 Compose 部署镜像，无需安装 Python 或自行构建源码。

### 1. 准备文件夹

```bash
mkdir -p /vol1/1000/docker/StrimKeep
cd /vol1/1000/docker/StrimKeep
```

创建 `docker-compose.yml`，可参考下方示例或直接使用仓库的 [完整 Compose 模板](docker-compose.yml)。

### 2. `docker-compose.yml` 示例

```yaml
version: "3.8"

services:
  strimkeep:
    image: ghcr.io/xcgtb/strimkeep:latest
    container_name: strimkeep
    restart: unless-stopped
    network_mode: host

    environment:
      TZ: Asia/Shanghai
      WEB_USER: "admin"
      WEB_PASSWORD: "CHANGE_ME_TO_A_STRONG_PASSWORD"
      # 1 = 启动时等待源文件挂载目录就绪；0 = 不等待。
      # 此项不是云端源文件联动删除的开关。
      ENABLE_CD2_WATCHDOG: "1"

    volumes:
      # 持久化配置、订阅、缓存、日志与 SQLite 数据库
      - ./data:/data

      # ① 本地 STRM 库：存放本地库的 .strm 文件
      # 清理本地 STRM 时，只有精确匹配到源视频且删除成功，才继续清理 STRM
      - /你的本地STRM库目录:/media/local:rw

      # ② 分享 STRM 库：存放分享库的 .strm 文件
      # 清理分享库只删除 NAS 上的 STRM 和附属文件，不触碰网盘源视频
      - /你的分享STRM库目录:/media/share:rw

      # ③ 网盘源文件库：挂载到 NAS 的真实视频文件目录（不是 STRM 目录）
      # 必须与①本地 STRM 库保持对应的相对目录结构；需验证可写、可删除
      # 只替换冒号左侧，右侧容器路径及 :rslave 保持不变
      - /你的网盘源视频目录:/media/cloud:rslave

    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"

    healthcheck:
      test: ["CMD", "python", "/app/scripts/healthcheck.py"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 20s
```

`version: "3.8"` 用于兼容仍支持该格式的旧版 Compose；新版 Compose 可能提示该字段已过时，不影响正常解析。**这并不意味着所有旧版 Docker 都能运行最新镜像。**

**部署时必须修改：** `WEB_PASSWORD` 和三处以 `/你的…目录` 开头的占位路径，填写 NAS 上**已经存在的真实绝对路径**。三个挂载点分别是：本地 STRM、分享 STRM、实际视频源文件；**只改冒号左侧**，容器内 `/media/local`、`/media/share`、`/media/cloud` 保持不变。无论使用 115、123 或光鸭，均按实际挂载目录填写。登录后再通过 Web 设置 Emby、TMDB 等服务参数。

> **目录与权限检查**：请在飞牛文件管理中确认上述目录已经存在、确实能看到需要的文件，并验证权限。源目录如只读、挂载断开或不支持删除，本地库源文件联动清理就无法完成。首次使用建议在独立测试目录验证；不要把尚未挂载的路径误当作空目录。
>
> **挂载就绪检查**：开启时会检查源目录的预期媒体分类。如果你使用不同网盘 / 分类方式，或者暂时只测试 Web，可把 `ENABLE_CD2_WATCHDOG` 设成 `"0"`。关闭等待不代表源文件联动清理一定可用。
>
> **密码包含 `$`**：在 Compose YAML 字面值中请写成 `$$`，避免被 Compose 当作变量展开。

### 3. 拉取并启动

```bash
cd /vol1/1000/docker/StrimKeep
docker compose pull
docker compose up -d
```

旧版 Compose 使用 `docker-compose pull` 和 `docker-compose up -d`，其余配置相同。

打开浏览器：**`http://你的NAS_IP:8321`**，以在 YAML 中设置的账号、密码登录。

默认使用 `latest` 镜像；需要升级时再次执行上述两条命令。希望锁定版本，可把镜像标签改为已发布的固定版本（如 `1.0.3`）。

## 首次使用

1. **检查映射**：确认本地 / 分享 STRM 根目录以及源文件挂载目录对应正确，特别是两侧相对目录层级。
2. **配置服务**：在 Web「规则设置 → 服务连接」中按需设置 Emby、TMDB、Telegram；网络受限时可设置 HTTP 代理。
3. **只扫描不删除**：进入「双库治理」，运行扫描并查看清单，核对同名影视、集数、画质结论和待删路径。
4. **调整治理规则**：检查七维顺序、多季保护、特别篇、白名单、默认 15 分钟入库静默期。
5. **手动确认执行**：只在结果和源文件匹配完全符合预期时执行；对不确定的条目先保留并排查。

### 文件删除与安全边界

| 操作 | 结果 |
| --- | --- |
| 双库扫描 / 计划预览 | 不删除文件 |
| 定时巡检 | 生成结果 / 通知，不自动执行治理删除 |
| 主动确认本地库治理 | 可能删除挂载源目录中的真实视频、其附属文件及 NAS STRM |
| 主动确认分享库治理 | 删除 NAS 侧分享 STRM 与关联附属文件，不联动删除分享云端源 |
| Web 手动删除 / 目录清理 / Telegram `/clean` | 根据确认范围执行真实删除，需谨慎授权 |

本地库源文件只有在**精确匹配**或**标准化后唯一匹配**时才进入删除流程；仅凭“目录里只有一个视频”等低置信度条件不会删除。源文件未找到、候选不唯一、无法删除或超时，对应 STRM 会保留并记录原因。删除前还会进行计划和实际文件状态复核。

> [!WARNING]
> 本项目通过挂载目录执行文件删除，**不是简单删除一个网盘链接**。云盘端是否有回收站以及删除能否恢复，取决于实际挂载服务和网盘；本项目不提供恢复保证。请仅在自己有权管理的媒体库上使用，并在执行前备份重要数据。

## 更新备份与排错

### 如何更新容器？

先在部署目录停止容器并备份 `data/`，再拉取镜像：

```bash
cd /vol1/1000/docker/StrimKeep

docker compose stop strimkeep
tar -czf "strimkeep-data-$(date +%Y%m%d_%H%M%S).tar.gz" data

docker compose pull
docker compose up -d
```

建议将备份文件另存至部署目录之外。`data/` 包含 `/data/state/strimkeep.db` 等运行数据，**更新镜像不能删除它**。从旧项目迁移时不要直接覆盖旧数据库；请阅读 [部署与迁移说明](docs/DEPLOYMENT.md)。

### 115、123、光鸭可以直接切换吗？

不是只改个网盘名称就能保证可用。StrimKeep 不绑定 115 专属删除 API，实际仍需满足：**上游 STRM / 302 链路可用、可写挂载路径真实存在、本地 STRM 与源目录层级及文件名可正确匹配、挂载驱动能把删除可靠传递到网盘**。请先在隔离测试目录验证。部分历史界面提示仍使用“115”作为习惯名称，不代表只能使用 115。

### 为什么能够看到 STRM，却删不了网盘源文件？

重点检查 `/media/cloud` 映射是否指向真实视频所在目录、文件名与相对层级是否对应，以及挂载权限、驱动删除行为和网络延迟。**安全策略会在匹配不确定或删除失败时保留 STRM**，这是预期行为，不要为了删除成功而关闭保护。

### 必须搭配 Emby 吗？

Emby 是当前媒体库映射、入库统计与缺集等增强功能的主要集成对象；双库 STRM 文件扫描与治理预览本身可以独立运行。这里主要面向 **302 STRM + Emby** 用户，不额外宣称其他播放器已完成适配。

### 代理、反向代理和日志怎么办？

在 Web 的服务连接页面配置外部 HTTP 代理；反代域名访问遇到 Origin 校验 403 时，按 [部署指南](docs/DEPLOYMENT.md) 配置 `ALLOWED_ORIGINS`。容器日志可通过 `docker compose logs --tail=100 strimkeep` 查看，SQLite 运行记录和治理计划在 Web 中查看。

### 无法启动、挂载目录为空怎么办？

先运行 `docker compose config` 检查配置，再执行 `docker compose ps` 与 `docker compose logs --tail=100 strimkeep`。重点核对镜像是否成功拉取、8321 端口是否被占用、宿主机三个媒体目录是否真实存在、是否挂载到了预期媒体分类。Docker 可能自动创建不存在的宿主机目录；**容器能够运行不代表媒体目录已挂载成功**。

### 忘记 Web 登录密码怎么办？

修改部署目录中 `docker-compose.yml` 的 `WEB_PASSWORD`，然后执行 `docker compose up -d` 使容器重新创建并载入环境变量。不要把真实密码放到 Issue 或日志截图。

## 技术栈

- **后端**：Python 3.11、FastAPI、Uvicorn
- **前端**：HTML、CSS、原生 JavaScript（无前端构建工具依赖）
- **数据存储**：SQLite（持久化数据目录 `/data`）
- **部署**：Docker / Docker Compose，单容器运行，默认端口 `8321`
- **适用生态**：Emby、TMDB、Telegram Bot；115 / 123 / 光鸭相关 302 STRM 方案；CD2 文件系统挂载与 OpenList 等 302 服务
