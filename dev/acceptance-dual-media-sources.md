日期：2026-10-20。基线为 v1.6.4，提交 daec694eac23941359414ce883a878fcc459947b。本次修改未打标签、未推送或部署，不移动旧媒体、不改真实 NAS 配置。

## 行为验证

- 四个真实临时根目录分别放置 STRM，按上游/自建、个人/分享得到独立数量及正确汇总；相同 URL 的不同文件分别计数，跨来源硬链接只计一次。
- 从未核验且尚不存在的新输出为待核验，不写成已核验零；已核验的自建挂载消失时保留完整统计快照。个人/分享来源重叠时拒绝发布错误统计。
- 自建目录的入库事件增量更新正确来源与汇总，重复事件不重复增加；来源状态接口只读缓存，不遍历媒体，未登录返回 401。
- 四个 Emby 根分别正确分类和严格转换；反向删除通知映射到对应来源，不接受上级跳转，同一 Emby 根指向不同 NAS 目录时拒绝猜测。片库卡片显示来源标签而不泄露原路径，详情保留明确来源。
- 治理仍以现有开关显式接入自建，不因显示数量改变权限。上游与自建真实硬链接在治理合并时去重，陌生自建个人引用不能进入旧路径删除。
- 混合来源删除先核验每个文件，再按根目录派发；预览明确列出上游与自建数量，跨根进度不重置。
- 实际 SQLite、真实临时 STRM、持久步骤与受控 115 提供方验证自建文件处于旧根之外时的清理：登记视频 ID 4、字幕 ID 5 被核验删除，NAS 引用撤销，原 CD2 路径猜测函数未被调用。该测试不接触真实 115 账号或 NAS 媒体。
- 原上游删除、批量清理、停止/未知结果保护与 1.6.4 Web 并发回归继续运行。

## 部署与限制

保持 StrimKeep 上游及自建两套挂载并存；确认 Emby 也实际可见自建宿主目录，再在全局连接设置中分别填写自建两库路径。账号级生成入库连接仍按其实际映射核验。确认挂载后手动刷新总览，再同步 Emby 片库。具体步骤见 docs/DUAL_MEDIA_SOURCES.md。

读取状态和打开页面不会扫描全库；完整统计在后台核验。存在硬链接/挂载别名或来源根配置变化时，不按简单目录增量猜测数量，等待完整核验。旧的空目录/残留清理工具不会因接入新来源而自动扩大写入范围。

本环境未连接真实 NAS、Emby 或 115；无法确认实机挂载权限、Emby 当前可见路径、运行中镜像 SHA 或媒体数量。接口与文件测试不能代替上述实机条件。
