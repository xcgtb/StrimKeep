# 海报加载与片库分页优化

基线：80e532963b94a37630e2ce2be3d5158b64967f91；最近发布标签 v1.2.0。本改动属于未发布，不移动标签、不改运行版本。

## 用户可见行为

- 片库映射默认每页 40 条，筛选、分类、库别、片名搜索和排序先在全量缓存数据上完成，再分页。limit 最大 80。点击作品才读取完整详情，包含原有分季、删除按钮与手动完结。无缓存时保留旧流程；失败不会假装片库为空。
- 翻页遇到事实版本变化回到第一页；旧筛选的列表或详情响应不覆盖新选择。SSE / 现有轮询仍负责事实变动通知。刷新同一作品时保留已解码海报节点，更新文字和角标。
- 两页卡片根据实际宽度与设备像素密度选择 w342 / w500。未指定尺寸的旧 URL 仍支持 w500；不改变 TMDB 优先、Emby 兜底顺序。Emby 由服务端请求 MaxWidth 与 Quality=90，不在容器做图片转码。
- 删除流程、云端配对置信度、云端先删顺序、保护规则、订阅投递和双库扫描算法均沿用基线。分享库删除仅删 STRM，本地库仍显示原真实进度；另一库有文件时保留海报。

## 资源与缓存上限

| 层 | 上限 / 规则 |
|---|---|
| 前端网络 | 两页共用 6 个请求槽，前台优先；预热最多占 1 个，前台图片忙时不启动预热 |
| 服务端图片 | 6 个不同图片任务，同图合并请求；单图最多 2 MiB；拥塞返回 503，前端最多重试一次 |
| 服务端内存图片 | TMDB / Emby 共用 16 MiB、128 张 |
| 持久化图片 | DATA_DIR/poster-cache-v1，64 MiB、256 张；原子写入临时文件最多额外约 2 MiB；只清理自有图片文件 |
| 图片有效期 | TMDB 24 小时、Emby 1 小时；Emby 主机或密钥变化使用另一缓存键，磁盘不存明文密钥 |
| 浏览器图片 | 原有 20 MiB / 64 张内存上限；CacheStorage v2 保留最多 120 条，写入分批清理；缓存查找最多等待 100ms |
| 片库分页 | 保留一份缓存事实索引，不重新扫描 Emby；最多 8 个筛选组合，60 秒或源修订变化重建 |

CacheStorage v2 第一次访问需要重新填充；旧 v1 缓存未被全局清除。前台缓存命中不需要外部下载，首次打开尚未缓存的海报仍受网络影响。已启动请求不会全部因切页强制中断，过时的排队任务会丢弃。

## 验证与边界

完整 Python、全部前端回归、静态资源哈希、发布边界及干净安装复验结果随补丁附带。测试使用临时数据、模拟网络与 DOM，不操作 NAS / 115 文件。

性能对照是模拟固定网络延迟和合成 5000 部片库，衡量下载次数、分页响应字节及缓存复用；不是实际飞牛速度保证。首次索引建立仍处理全量缓存，长期滚动仍累计当前筛选的浏览器卡片。

此环境没有 Docker；未声称 Docker 构建、真实飞牛 / Emby / TMDB 网络或手机电脑视觉验收通过。正式部署仍使用现有 Compose，不覆盖挂载、配置和 data。
