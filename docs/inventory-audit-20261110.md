# 双库治理与片库映射审查记录

基线：线上 0.9.99 源码的隔离副本；对照：1.2.12 的 `app/domain/governance.py`、`app/domain/quality.py`、`app/governance.py` 和片库映射前后端。对照文件通过该副本的 MANIFEST 校验。此副本不是线上部署版本。

## 已复现并在隔离副本修复

- 同一季有两条相反方向的残次品结果时，执行层曾按作品和季覆盖其中一条，导致单项报胜方变化、批量报重复。按动作方向及原因匹配，禁止单次同时删除同季两库。
- 同一维度双方都未知时，治理比较不再提前把后续维度都当平局；例如 1080p 60fps 对 1080p 24fps 会继续比较帧率。文件大小始终不参与 STRM 文件名比较。
- 特别篇 S00 可作为季 0 提交；设置更新保留没有提交的字段。页面展示决策模型、多季保护、特别篇和豁免词。
- 单库电影多版本此前未进入治理；单库多版本结果缺少作品身份；单库独有季的前序缺失和跳集此前无清理项。现已补齐这些入口。
- 合并集文件不能当普通单集比较或归并到同一组，现标记为待核实，不自动删除。
- 映射状态绑定库存文件版本并设置有效期；TMDB 或库存不完整、播出日期未知时不再标记完整。页面防止旧筛选请求覆盖新结果，并显示未核实记录数量。
- 残留清理请求不再携带未被接口接受的 backup 字段；默认直接清理，经核实后不生成附属文件归档。

## 尚未证明等价或仍需完成

- HDR Vivid、Audio Vivid / AV3A 已加入现有规则，并补充 `E-AC-3` 等文件名识别。现有洗版规则的音频比较优先考虑声道，再比较编码；1.2.12 的格式档位不同，音频裁决不能认为完全相同。
- 洗版策略没有启用有效维度时会阻止依赖质量的治理，不能默默按平局方向删除。
- 单库多版本或残次先行清理；多季保护依赖整个保护组，有残次季时会暂停该组双库动作。保留方不覆盖被删除方所有集号时也阻止删除。这些保护有意比 1.2.12 更保守。
- 合并集暂时保守阻止自动治理，尚未实现按文件原子性正确比较、保留和删除。
- 前端构建、规则和隔离文件操作测试不能代替真实 115、Emby、TMDB 联调。不得凭这些结果宣布可以对真实媒体库执行清理。

审查时线上容器是 0.9.99，NAS 开发 Git 仓库仍在 0.9.97。两者不能直接覆盖；合并前需再次核实工作区、线上镜像和源码版本，保留可回退的开发版本与数据快照。
