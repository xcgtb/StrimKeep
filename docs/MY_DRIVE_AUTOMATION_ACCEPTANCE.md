# 整理自动化：Cron、空目录与延时 STRM

日期：2026-10-15。基线为 GitHub main/v1.3.4 `4b52763`，此次增加源码能力，未推送、未打新标签、未构建或检查飞牛生产镜像。历史最高可达语义标签 v1.12.11 保留；本次实际发布基线为 v1.3.4。部署 YML、依赖和原七维治理不变。

## 本批效果

| 功能 | 使用位置 | 实现行为 |
| --- | --- | --- |
| Cron 自动整理 | 影视整理 → 自动整理任务 | 选择按分钟或 Cron，填写时区，试算下次时间，保存启用、暂停或移除 |
| 独立定时 STRM | STRM 生成 → 定时同步 | 单独规则，不改名或移动源视频；支持间隔/Cron、下次时间、暂停/启用 |
| 独立 STRM 来源 | STRM 生成 → 选择来源目录 | 保存 `strm` 角色到当前账号，影视整理的 `source` 不变；旧账号未设置时明确提示沿用整理来源 |
| 空目录清理 | 影视整理 → 整理配置 | 默认关闭；清理本批成功移走视频后腾空的来源子目录，结果和回执写入历史 |
| 延时生成 | 影视整理 → 归档完成后延时 | 默认 0 秒立即；可设 1–86400 秒，逐视频完成归档后保存独立待执行任务 |
| 同步停止 | 整理历史与任务 | STRM 同步可在当前视频及关联输出完成后停止，不对未扫描完的目录做来源撤销对账 |

## 操作

1. 在影视整理选择来源与归档目录。按需启用清理空目录，设置 STRM 延时秒数，再点“保存整理配置”。
2. 识别预览显示可能需要检查的来源子目录数量。执行确认包含空目录清理和延时提示；取消不执行。
3. 勾选“整理后生成 STRM”时延时生效；关闭该勾选不会产生延时任务。延时不是暂停整理线程，后面的影片可继续归档。
4. 在历史中查看每个已完成视频对应的待生成任务和到期时间。待执行任务可取消，取消不会还原已经归档的视频。安全停止整理保留此前已完成视频的联动任务，需取消时逐项取消。
5. 自动整理任务选择 Cron，例如 `0 3 * * *`，时区默认 `Asia/Shanghai`，先试算再保存启用。原按分钟规则继续可用。
6. 到 STRM 页单独选择归档库作为来源，并配置定时同步。它只扫描、生成/更新、对账及请求 Emby 刷新，不执行云端改名或移动。

规则保存当时的账号、凭证版本与目录 ID；后续改目录选择不修改已建规则。整理规则执行时采用当前已保存的全局整理配置。暂停和移除规则停止未来触发，已有排队/执行任务应在历史中另行停止或取消。

## Cron 范围

使用 Python 标准库，不新增 cron 依赖。支持五段数字 `分 时 日 月 周`、`*`、逗号、范围和 `/` 步长；不支持秒字段、年字段、英文名称、`L/W/#/?` 或 `@daily`。周日接受 0 和 7。日与周同时指定时按任一匹配；有通配开头时按两者共同匹配。最多查找未来八年，非法时区和不可到达日期在保存前拒绝。

使用 IANA 时区；春季不存在的当地时间跳过，秋季重复时刻按两个真实时间处理。规则下一次触发严格晚于计算时刻。停机或任务占用时错过的触发合并一次，不生成逐次补跑；同一规则已有排队/运行任务时不重复入队。凭证变化会暂停规则并显示原因。

语义参考：[crontab(5)](https://man7.org/linux/man-pages/man5/crontab.5.html)、[Python zoneinfo](https://docs.python.org/3.12/library/zoneinfo.html)。镜像已安装 tzdata。

## 延时核验

新增 `cloud_job_due` SQLite 表，任务与到期记录在同一事务保存；同一原任务/视频只登记一次。到期前工作线程和领取函数都拒绝执行。重启后尚未领取的任务继续保留；重启前已运行且结果不明的任务沿用原“需要核实”，不重放写入。

任务保留已识别媒体、完成归档的视频和关联文件快照，执行前核对账号凭证版本、所有文件指纹/位置、归档祖先链和 STRM 输出配置。发生变化则停止该任务，用户核对后从 STRM 页重新同步，不重新猜测作品。成功生成后请求 Emby 刷新；刷新失败历史显示待处理。联动期间视频尚未生成 STRM，不会提前标记可播放。

## 空目录范围和边界

只选取本次成功移走视频的原父目录及其来源范围内祖先，按从深到浅清理。保留根目录、来源根目录、归档/未识别/转存/STRM 配置目录，也保留原有无关空目录。视频被过滤、附属文件未跟随或有其他内容时，目录不为空，会保留。整理出错或停止时不启动后续清理。

每次清理重新核对目录名称/ID/父目录及整条来源祖先链，完整读列表判空；适配器在发送前再次检查空目录。删除意图和结果持久保存，结果不明停止清理、保留已完成整理记录，不重复删除。未使用 SDK 的全账号 `tool_clear_empty_folder`，也不清空回收站。

115 的 `fs_delete` 不是带原子“仅空目录”条件的删除接口。双重核对仍无法锁住其他客户端在核对和删除之间的写入，开启前应避免来源目录同时被其他程序写入；真实账号上仍需验证目录查询和不存在回执。默认关闭，不把目录存在查询失败当成删除成功。
