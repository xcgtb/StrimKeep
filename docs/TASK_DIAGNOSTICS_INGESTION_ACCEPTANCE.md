## Emby 已有电影但网页空白

原 `watch()` 在全局联动关闭、没有独立启用连接或缺少此来源映射时直接返回，没有 `cloud_ingestion` 记录。网页只读取该表，且打开后不自动更新；Emby 自行扫描成功并不保证网页有记录。这是源码确认的缺口，不能据此认定用户这部电影一定是哪项配置导致。

| 条件 | 更新后网页行为 |
| --- | --- |
| 当前账号已生成 STRM，未启用全局联动 | 显示“STRM 已生成 · 尚未核验”，说明联动关闭 |
| 未配置或未启用独立入库连接 | 显示已生成记录，提示填写地址、Key 与映射并保存 |
| 只映射个人库，文件来自分享库 | 明确提示此来源缺少路径映射 |
| 生成后才补齐连接 | 打开/刷新记录时补登记最近活动 STRM，交给后台核验 |
| Emby 已经扫描到该电影 | 补登记项先按精确路径和 TMDB 读取；匹配后直接确认，不再次请求刷新 |
| 尚未扫描到或身份不匹配 | 保持等待；按已有机制提交相应路径刷新，绝不把刷新提交当作入库成功 |
| 核验超时 | 保留超时记录，读取网页不会自动重置重试计数 |
| 修改连接配置 | 为当前配置登记核验；历史配置记录有明确标注 |
| 引用已撤销或摘要/本地路径已变化 | 不作为当前引用的入库证据展示 |
| 已确认后停用联动 | 既有已确认凭据保留，不把已确认事实改成未入库 |

读取记录只补本地登记，不在请求中访问 Emby、不重新生成 STRM、不重新转存。后台仍严格核对路径、TMDB，以及剧集的季、集和剧集身份。没有复用其他服务的凭证，也不向 Telegram 再发一张海报。

页面展示最多 100 条记录，并补齐当前账号最近 100 个活动引用；这不是 Emby 全库列表。打开播放页面后每 15 秒更新一次网页状态，后台待核验项约每分钟重查。离开播放页取消该页面定时器，账号变更丢弃旧响应，保存连接后立即刷新记录。
