# TG 频道监控

把公开频道里新发的 115 分享链接，接进「分享 STRM」管线：免转存、自动识别整理、
生成 STRM、按通知设置告知 Emby。

## 为什么读网页预览，而不是走 Telegram API

三条路都试过，只有第一条对「别人的频道」成立：

| 方式 | 卡在哪 |
| --- | --- |
| Bot API `channel_post` | **只有 bot 是频道管理员才收得到**。资源频道是别人的，你加不进去，这条直接死。 |
| MTProto 用户会话（Telethon/Pyrogram） | 要 my.telegram.org 的 api_id/api_hash + 手机号登录 + 维护 session，等于把你的账号挂上去跑自动化，还有 FloodWait。 |
| **公开预览页 `t.me/s/<频道>`** | Telegram 给所有未登录游客渲染的纯 HTML，20 条一页，`?before=<消息ID>` 往回翻。无需登录、无需 bot 权限、无需 api_key。 |

代价是清楚的：只看得到**公开频道**，只看得到**最近的消息**，拿不到评论、投票细节和编辑历史。

## 怎么用

1. 设置 → Telegram 通知 → 频道监控。
2. 打开开关，在「公开频道」里输入 `@频道名` 回车（也接受 `https://t.me/频道名`，邀请链接会被拒）。
3. 保存，点「立即检查一轮」。
4. 第一次检查只登记游标（表里「跟进到」会出现一个消息 ID），**不会**把历史帖子灌进来；
   之后每轮只看比游标新的帖子。

轮询间隔默认 300 秒，最小 60 秒。间隔在设置页可改。

## 抓到什么

- 正文与内联按钮里的 `115.com/s/…`、`115cdn.com`、`anxia.com` 链接
- 正文里的「提取码 / 访问码 / 密码: abcd」
- 一条帖子最多 10 个分享（与手动 `/share` 同一限制）

## 去重

| 场景 | 机制 |
| --- | --- |
| 同一条帖子被重复读到 | `channel_posts` 按（频道, 消息ID）认领，只处理一次 |
| 同一个分享被不同帖子转来转去 | `channel_shares` 按 share_code 去重 |
| 频道一次发了很多条，超过一页 | 游标没追上就自动往回翻，最多 2 页（40 条） |

## 频率与礼貌

- 每次请求 `t.me` 之间至少 1.5 秒（翻页也算），不分频道还是分页，统一排队。
- HTTP 429 → 该频道标记「限流退避」，本轮不再碰它。
- 拿不到预览（频道不存在 / 未公开 / 被限制）→ 标记「读取失败」并在表里写原因，不影响其它频道。

## 边界

- **只能监控公开频道**。私密频道、群组没有预览页，这一版不支持。
- 首次接入不回溯历史；要看老帖子得手动 `/share`。
- 帖子被删、被编辑，预览页给的是当前状态，历史版本拿不到。
- 只按用户名识别频道；频道改名/换用户名需要手动更新配置（不做名称匹配，避免同名顶替）。
- `t.me` 在你所在网络不可达时，整块功能会一直「读取失败」——先确认 NAS 能直连 t.me。
