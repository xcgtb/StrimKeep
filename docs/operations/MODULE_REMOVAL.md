# 双库治理、片库映射移除说明

基于用户提供的 StrimKeep(7).zip 修改，其他业务沿用原包。

## 已删除

- 双库治理和片库映射的页面、菜单、页面缓存注册、接口、后台业务实现。
- 片库盘点任务、治理执行任务、定时盘点及自动治理调度、任务中心专用展示。
- 两个模块的旧专项测试、对照文档以及 local-patches 下随原包附带的三组旧源码备份。
- 旧前端构建文件；随包提供重新编译的前端资源。

## 首次启动时的旧数据清理

取得单实例锁后、启动后台任务前，执行可重复的 SQLite 事务：

- 删除 mapping_entries、mapping_works、mapping_snapshots、governance_plans 四张专属表。
- 删除 mapping_config、governance_config、governance_policy 三项配置，以及 mapping_revision、governance_last_scan。
- 删除 mapping_rebuild、governance_execute 专属任务及其子项、通知、Emby 投递和对应定时记录。
- 删除 mapping、governance 两类专属事件日志；普通文件操作审计仍保留。
- 对原模块派生的输出修复/恢复任务，保留已有处理证据，取消未完成任务并移除旧模块来源标记。
- 未知或已移除的任务类型直接取消，不会误入普通整理流程。

清理只操作本地数据库元数据，不调用 115 文件删除、不删除任何现有 STRM、字幕、NFO 或视频。
共享的播放记录、撤销记录、输出登记、整理记录和洗版规则保留；已经撤销的分享不会因移除模块而自动复活。
后端中保留的旧模块名称仅供旧数据清理使用，测试中仅用于验证移除成功。

## 保留能力

普通影视整理、原有洗版及杜比等质量规则、链接转存、离线下载、分享 STRM、STRM 同步、影视探索、Emby 通知和 Emby 路径映射。
“Emby 路径映射”用于容器挂载路径换算，是播放/入库基础功能，与此次删除的“片库映射”页面不同。

## 更新

将本包解压到独立目录，在新包根目录运行：

```bash
bash update.sh /现有StrimKeep项目的绝对路径
```

脚本替换程序目录、清理原包已知旧备份并重新构建容器，保留目标环境的部署配置和持久化目录。
不要仅覆盖几个文件：覆盖不会删除旧模块源码。使用 update.sh 完成目录替换。
本包不含 Git 历史、node_modules、Python 缓存与运行数据库。
实际 NAS 上的 115 / Emby 联网行为需部署后验证；本次未连接用户的线上服务。
