# STRM 同步和失效输出

STRM 是给 Emby 读取的本地文本链接，视频仍在 115。115 删除源视频后，旧 STRM 可能仍然在媒体库里显示，但播放时无法取得源视频；网络故障、登录过期和分享暂不可用不等于源文件已经删除。

## 目前怎么使用

在「STRM 管理」选择要同步的 115 来源目录，然后手动开始同步；也可以在定时任务中设置同步时间。当前手动与定时同步都会重新发现所选范围，不是 115 生活事件增量同步。整理任务会在入库时增量处理已确认的目标目录。

「全量同步后自动清理失效的本地 STRM」打开时，完整扫描结束后，程序只处理本账号、本次所选范围的受管输出：不在清单里的文件还要实时核实云端状态，并检查本地归属和文件内容。网盘源文件被删除或已移出所选范围时，清理已登记且内容未变的本地输出；不会删除 115 网盘文件。范围本身被移除、云端读取失败、本地文件被修改、归属不清或扫描后才登记的输出，均保留待核查。关闭开关时不执行这项清理。

分享 STRM 由分享播放与分享存活流程管理，不能因为它不在自有 115 网盘清单中就判定失效。深度删除是另一个方向：从 Emby 的删除事件触发联动，可能涉及网盘文件，需单独配置。

目录完成通知包含目录读取耗时、本地复用数量和重新处理或待核查数量；任务总耗时还包含排队与其他处理。高请求量时先看是否有大量文件需要重新核实，避免单纯调低 115 请求间隔。

历史遗留的失效列表 API 并未接入当前页面的全量同步结果，不能将其当作自动生成的待清理清单。手动清理旧列表也要求核实当前账号、已登记的归属及文件内容。

## 后续优化方向

可以研究基于 115 生活事件的增量发现，定期完整对账作为兜底；断线、事件缺失、权限或账号变化时必须回退到完整核对。当前版本尚未提供完整的事件增量能力，不应把本地巡检称为云端增量同步。对大库优先保留整树清单、按文件指纹与目标路径复用、只处理变化项、按受影响路径通知 Emby，并保持请求节流。
