# 同步核查与局部隔离（2026-10-29）

## 核查结论

-  运行日志多次出现“115 子脚本同步完成，退出码：0”，表明相应同步过程曾有子脚本。当前进程列表本身不能确定任一子进程的具体职责，也不证明发生故障时所有网页请求都不受影响。
- 原先的 `0 0 * * *` 是每天零点，不是每小时。
- StrimKeep 的整理、转存、同步是单进程中的独立 asyncio 车道，异步协作并不等于进程隔离。它们共享同一套进程内发布锁、扫描与转存锁，以及 115 请求节流；简单换成独立进程会破坏这些共享约束。
- 当前同步支持近期清单复用：仅定时、非强制全扫、快照未过期且目录、版本、输出核验通过时复用；手动同步仍重新扫描。外部变动可能在缓存期限内未被立即发现，不能把缓存说成完整实时清单。
- `ffprobe` 本来就是限时外部进程；是否按文件名跳过探测会改变质量判定依据，不能仅凭文件名替代技术事实。

## 本次修改

同步快路径中的受管输出文件 SHA-256 校验交给独立只读子进程；主进程仍负责云端请求、数据库和输出操作，继续使用原有锁与限流。子进程不接收凭据或直链，校验请求在子进程退出时最多重试一次；持续异常使任务进入待核查，不执行清理。每个同步任务结束时回收子进程。读取过程中检查文件身份和大小，文件发生变化时不复用旧结果。

三条任务车道由监护协程看管。车道异常退出后，原先运行中的本车道任务标记为待核查，不自动重放可能已发生的外部操作；其他车道保留状态。健康检查覆盖同步、转存和整理车道。

这不是完整的同步业务子进程隔离：Python 主进程崩溃仍会影响整个服务。要实现完整隔离，须先设计跨进程的发布/清理/接收互斥、统一 115 节流与冷却、任务认领租约和断电恢复，再逐项验证并发与故障场景。

隔离测试中使用 256 字节本地文件，400 次子进程校验约 1.16 秒；这不是网盘扫描或真实同步的速度承诺。
