# Telegram 海报详情通知

## 本次行为

- 追更订阅每部作品发送独立通知。海报与 HTML 详情属于同一条 `sendPhoto` 消息。
- 详情包含作品、年份（有事实时）、新增季集与数量、补齐季集、待补集、片库已有数量、受影响季数量、可确认的本地/分享库数量、TMDB 标识、片库事实来源。没有可确认的版本/体积/发布组时不显示，不填零或推测。
- 电影与资源入库订阅同样使用海报详情；电影展示当前版本数及已知双库版本数。追更已覆盖的剧集保留原有通知去重。
- 海报优先使用当前片库信息，其次订阅海报和已查询的 TMDB 信息。复用现有缓存，图片上传到 Telegram；Telegram 不需要访问内网或携带 Web 登录凭据。只解析受支持的 TMDB/Emby 海报路径，不请求订阅任意外部地址。
- 无图、下载失败、不支持图片格式或图片请求明确被拒绝，发送完整文字详情。详情文字超过 Telegram 图文长度限制时发送完整文字。图片发送超时、限流、鉴权失败和服务端故障保留队列重试，避免结果不明时再补发另一条消息。
- 晨报保留折叠入库清单和缺集清单，去除规则/事实哈希，改为可读更新时间；保留 TMDB 对照过期、逐部检查失败、等待发送提醒。

## 投递与兼容

不修改原订阅基线、集数差集、首次订阅静默、暂停边界、删除保护和队列背压规则。
每部卡片成功后保存 `delivered_sids` 回执。批次未完成时，重试跳过已成功卡片；完成后再提交批次订阅状态和每日汇报。时间预算/关闭信号在卡片之间检查。已经成功的卡片即使随后暂停，也保留状态恢复；尚未发送的暂停项取消。

Telegram 无客户端幂等键：远端已接受但进程在回执写盘前退出/写盘失败，或发送超时结果不明，重试仍可能重复。不能宣称严格恰好一次。
旧队列不需要迁移：没有新详情字段的待处理项仍可发送基础卡片；成功历史继续压缩，不保存图片字节。

一般无须重建订阅或修改 Bot 配置。只对后续新增、补齐或缺集变化发送通知；升级不会重发全部历史集。Bot 需要能向已有 Chat ID 发消息和图片，服务需要能访问 Telegram 与配置的海报源。

## 离线验证与实机验收

测试覆盖 multipart 上传、Telegram JSON 成功确认、图片拒绝与缺图降级、超时/限流保留重试、海报来源限制、字段转义、零值与未知值、重复身份不叠加数量、逐卡回执/暂停/停止/重启恢复、晨报过期及积压提示。测试模拟网络，不发送真实 Telegram 消息。

部署后等待一部已订阅作品出现真实新增集，确认一条海报消息包含正确季集和两库数据；无海报作品应收到文字。查看 Web 待发送数及错误提示确认投递结果。源代码检查和离线测试不等于 NAS/Docker/真实 Telegram 验收；本包不操作媒体、/data、运行容器或发布标签。
