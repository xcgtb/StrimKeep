# 115 转存、整理与身份绑定治理

本次在 xcgtb/StrimKeep 的 v1.2.10 源码上追加模块，基线提交为 `0ef48152b369761505d54229231449826d49e6a4`。按用户指定的 **v1.12.11** 准备发布；源码包本身不代表镜像已经构建，也没有更新运行中的 NAS。

## 已实现的效果

| 功能 | 行为 |
| --- | --- |
| 官方账号授权 | 用户自己的 115 开放应用 AppID + PKCE 扫码，或填写已有官方 Access/Refresh Token；查询官方 UID 后才保存 |
| 目录读取 | 手动读取选定账号的一页目录，最多 100 项；不后台扫描整个网盘 |
| 独立分享转存 | 同账号辅助 Web Cookie 读取/接收分享；官方授权创建独立暂存目录并核验新自有文件 ID，不调用 TgtoDrive |
| 转存来源登记 | 分享码与来源 ID 作为来源命名空间；目标账号 UID、目标文件 ID、大小和 SHA1 作为自有资产证据，持久保存双方对应关系 |
| 自建 STRM | 选定视频 ID 和本地库相对路径，写入本站稳定播放地址，登记账号、文件 ID、大小、SHA1/提取码和本地文件指纹 |
| 302 | 每次验证播放令牌、本地 STRM、账号和源身份，再取得短期直链；支持无额外请求头以及使用同一播放器 User-Agent 的直链 |
| 治理源删除 | 新绑定优先进入官方 ID 删除链，复用现有治理预览、互斥、任务、统计和本地清理流程；不要求 CD2 挂载可用 |
| 关联文件 | 每个视频最多 20 个明确选择的字幕/元数据；转存核验后保存关系，生成 STRM 和整理自动继承；主视频与关联文件不得被重复绑定，不按同名猜测 |
| 删除恢复 | 请求发出前保存意图；超时或结果不明保留 STRM，随后只查询原 ID；官方确认全部登记源消失后才允许清理 STRM |
| 旧 STRM 接管 | 仅接管 URL 中唯一显式 `pickcode`/`pick_code`，由官方接口解析并交叉验证 ID；保持原 URL；仅继承已登记的转存关联关系，不推断其他关联文件 |
| 只读复核 | 设置页可核验中断的生成任务和已有删除回执；不会重发删除或自动删除本地文件 |
| 按 ID 整理 | 为现有视频及明确选择的关联文件生成移动/改名预览，确认后逐步执行官方接口；不改变扩展名，不覆盖目标重名文件 |
| 整理互锁 | 未确认的整理步骤暂停同一源 ID 的治理删除和再次整理；只读复核已提交步骤后，可确认继续尚未提交的步骤 |

已形成用户确认的“115 分享转存 → 自有 ID 核验 → 按 ID 整理 → STRM/302 → 治理删除”流程。**分享转存使用显式辅助 Web Cookie，不宣称属于官方开放授权能力。** 官方 Token 负责自有目录/文件读取、整理、直链和删除。两种授权必须核验为同一个 UID。

**本次没有实现 TMDB 自动识别、无人值守整理、递归整目录转存、批量 STRM、123/光鸭授权。** 原 TgtoDrive 接入继续保留。绑定旧 STRM 不代表已替换其上游播放服务；新生成 STRM 使用本站播放入口。

## 和现有源码的兼容边界

- 按最新要求把 Docker 与 CI 基线升级到 Python 3.12；FastAPI、Uvicorn 等现有锁定版本继续使用，新增本地二维码依赖 `qrcode==8.2`。Emby/Telegram/订阅/七维策略及现有前端主题保留。
- 前端 CI 使用 Node 24，与本次实际回归环境一致；没有要求 NAS 额外安装 Node。NAS 仍按原 Docker/Compose 部署。
- SQLite 从 schema 4 追加到 6；新增账号、绑定、文件归属、删除回执和转存来源表；已有配置、记录与事实不重置。转存来源不会随最近 50 条任务历史裁剪而丢失。
- 两个新配置项默认关闭/空值。关闭「只允许身份绑定删除」时，未绑定旧 STRM 仍走现有 CD2 匹配链；有绑定但身份异常的文件始终停止，不回退。
- 开启「只允许身份绑定删除」后，本地库未绑定文件会保留并报告原因。分享库仍只清理 NAS STRM，不删除云端源。
- 删除成功的历史绑定和回执继续保留。同一路径可绑定另一个新视频 ID；新绑定不复用旧删除回执。被占用或结果未确认的路径不能覆盖。
- 原上游转存目标额外兼容文档中的 `data.transfer.targets`；不会把资源来源列表当作转存账号，明确未配置的目标不展示。
- 源文件更名或移目录只要 ID 和内容证据未变，可以继续核验；本地 STRM 被编辑、替换、移库或根目录改变会停止。此次尚未提供绑定路径迁移工具。
- 本站整理完成后同步绑定中的云端名称/父目录证据，不改写已生成 STRM，也不按新名称重找源文件。已有删除意图的绑定不得再整理。

## 在 NAS 上使用

1. 将完整源码包解压到现有 Git 工作区，使 `app/`、`static/`、`docs/` 直接位于根目录。保留部署目录的实际 Compose、凭据和 `/data`。包不包含运行数据或任何真实授权。
2. 依照 `dev/PUBLISHING.md` 构建并更新容器。该包不是已发布镜像；仅覆盖 Git 源码不会更新运行中的容器，普通 `main` 推送也不会触发版本镜像发布。
3. 在「设置 → 服务连接 → 115 官方接入」填写用户自己的开放应用 AppID 并扫码确认，或保存已有官方 Token。先确认返回 UID 属于预期账号。没有有效应用权限时，不能用 CD2 Cookie 或第三方 AppID 替代官方授权。
4. 保存 Emby/播放器能访问的本站地址，例如 `http://NAS地址:8321`。此地址不填账号密码或 Token；反向代理前缀需实际转发 `/play/115/`。
5. 读取隔离测试目录，选择视频生成 STRM。使用 Emby 实际播放确认 302 和播放器跨域 User-Agent 行为。
6. 先对隔离目录执行治理预览，再实际清理一条测试视频及明确登记的字幕。检查云端对象、绑定状态和本地 STRM，不以接口接收请求作为删除成功。
7. 旧库按显式提取码逐条接管并核验；完成迁移后再开启严格绑定模式。没有显式提取码的旧文件暂不自动接管。

### 独立分享转存

在 115 面板的「独立分享转存」中，为选定的官方账号保存同账号 Web Cookie。填写 `115.com/s/…` 分享地址及其访问码，在分享目录分页中选择一个视频和最多 20 个确知属于该视频的字幕/元数据，再填写已有暂存父目录 ID。

点击预览不会创建目录或转存。核对来源 ID、账号 UID 与目标父目录后确认执行：官方接口先创建随机命名的专用暂存目录，辅助 Cookie 再接收明确选择的分享文件；官方接口逐项核验该目录内的自有 ID、父目录、大小、SHA1、类型和完整数量。已存在的其他目录和同名视频不作为接收结果。

成功记录中的「整理 / 生成 STRM」操作只传递核验后的自有文件 ID，不能将分享来源 ID 用于自有网盘删除。明确选择的关联文件会自动继承到后续整理与 STRM 绑定。已核验目标仍存在时，重复转存同一来源会停止；目标明确消失后允许建立新的来源记录。

源文件需有可核验 SHA1；缺少 SHA1、同一组选中多个相同内容文件、目录分页不完整或暂存目录出现额外对象时停止。当前每次处理一个视频及本页关联文件，不递归转存整个分享目录。目标父目录和整理目标目录最多核验 1000 项。

转存/创建目录超时，去记录中只读复核：已提交请求不重发，只核验原暂存目录与原文件证据。只有尚未提交的接收步骤可以在核验后再次确认继续。未知任务不能通过重新预览绕过。取消也不删除已经创建的暂存目录，不执行递归云端清理。

整理时从目录文件条目的「整理预览」进入，填写现有目标目录 ID 和保留扩展名的新名称；关联文件按明确 ID 选择，可分别指定新名称。核对完整预览后点击「确认按 ID 执行」。目标目录最多核验 1000 条，无法确认全部分页或存在重名就停止；当前不自动创建云端目录，也不推断 TMDB 归属。

整理请求超时后，去「按 ID 整理记录」只读复核。原 ID 的父目录、名称和内容证据全部符合该已提交步骤后才标记确认；只允许继续尚未提交的步骤，不重发未知写请求。没有提交过任何步骤的计划可取消；已经提交而结果不明的计划必须先核验，不能用取消抹去操作意图。

如果逐步停用 CD2，在**实际部署目录**将 `ENABLE_CD2_WATCHDOG` 改为 `"0"`，避免现有 CD2 守门员因缺少挂载而重启容器。保留本地/分享 STRM 挂载；本阶段官方绑定删除不访问 `/media/cloud`。尚未迁移的旧文件仍可能需要 CD2。

## 测试和未验证条件

自动测试使用临时目录、临时 SQLite、模拟官方响应和实际本机 HTTP 服务，不操作真实 115 或 NAS。覆盖文件/账号冲突、关联文件冲突、请求超时、只读恢复、路径逃逸、覆盖防护、分享库边界、授权轮换、PKCE、302、令牌不回显及前端旧响应隔离。

执行命令：

```bash
python dev/tools/static_check.py
python dev/tools/release_check.py
pytest dev/tests/ -q
node dev/tools/update_frontend_asset_versions.cjs --check
node dev/tools/verify_frontend.cjs
python dev/checks/verify_docs_schema_compat.py
python dev/checks/verify_release_startup.py
```

真实账号的 AppID、授权范围、会员/直链限制、实际响应差异和 Emby 播放链路仍需上述隔离目录验收。需要额外 Cookie 的 `f=3` 直链会报错；当前没有内容代理、直链缓存或大规模播放限流队列。播放入口最多三个官方网络请求并发，繁忙时返回 429。未知/加密响应暂不作为文件不存在或成功依据。

Access/Refresh Token 和辅助 Cookie 存在已有私有 `/data` SQLite 中，管理 API 不回传；不是加密凭据仓库，应使用既有部署的数据目录访问权限。扫码会话结束会清除临时凭据。Cookie 仅发送到固定 115 Web 接口，官方接口使用 Bearer Token，转存适配器不用于治理删除。STRM 内的播放令牌只授权该绑定；本站 Uvicorn 日志隐藏播放查询参数和扫码会话标识（包括代理前缀），反向代理的访问日志也应隐藏对应令牌。
