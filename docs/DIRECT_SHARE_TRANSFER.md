# 分享转存目录 · v1.4.5

分享转存、机器人普通分享和频道接收中使用分享转存任务的路径，统一取消额外的「转存待整理-任务号」目录。保存目录仍使用已有账号配置，不需要修改 Docker Compose。

例如目标为 `测试`，分享内选择 `作品目录`，接收后是 `测试/作品目录/原视频.mkv`；如果选择的是视频，则直接成为 `测试/原视频.mkv`。分享原有目录层级保留。

勾选转存后整理时，仅将本次已核实文件及其关联文件交给整理命名和 STRM 生成。目标里原有的其他文件不会被该任务扫描；用户单独启动的全目录整理和已保存定时规则仍按各自来源配置工作。

## 回执与冲突

- 接收前记录目标目录身份和已有项目 ID；接收后按新增 ID、名称、类型、可用大小与 SHA1 核实顶层项目，并递归记录本次文件。
- 目标已有同名文件或目录时，任务停止并提示核对；不合并已有目录，不覆盖文件。
- 请求超时、结果尚不可见或有多个同名新增候选时保持待核实。任务页面核实只读取目录，不会再次发送接收请求。
- 核实后继续整理只读取本次收到的顶层项目。文件指纹或位置变化、目标目录身份变化时停止。
- 兼容升级前使用任务子目录的待核实任务。旧目录不批量删除，避免丢失未识别、过滤或未整理的内容；确认旧目录为空后可自行删除。

`dev/tests/test_cloud_direct_transfer.py` 使用有状态远端夹具及真实 SQLite / 本地 STRM 输出验证直接接收、递归目录与字幕、排除其他文件、冲突、超时核实和继续、旧版回执、根目录及异常状态。真实 115/NAS 接收效果仍须在部署后确认，自动测试不作为真实网盘验收。
