# Emby 实时增量同步

本次源码基线为 main 的 3b41aa2（最新可达正式版本 v1.2.0）。不修改版本号，不改变七维治理、STRM 配对及云端优先删除规则。

## 开启方式

1. 更新容器并刷新网页。在 Web 入库监控设置中生成回调地址。
2. 在 Emby 的 Webhook 插件/回调能力中填写这个地址，选择媒体新增及删除事件（library.new / library.deleted；若服务支持 library.updated 也可选择）。回调目标必须是 **Emby 服务器能访问的** StrimKeep 地址；网页生成地址使用当前访问域名，可替换地址的主机部分，保留路径和 token。
3. 发送测试事件，重新打开设置确认收到回调。测试、播放、用户等非媒体事件不会修改片库。
4. 将监控模式切换为“Emby 实时回调”并保存。首次切换后台执行一次完整初始化，建立片库事实和 STRM 目录统计基线。默认全量校准间隔 24 小时，可调整 1～168 小时。
5. 用一次实际入库验证回调时间、待处理数量、三页状态及已订阅作品通知。Emby Webhook 功能是否可用取决于其安装版本、插件和授权；本补丁不会自动安装或配置 Emby 插件。

旧安装默认继续使用定时增量模式，避免没有配置 Emby 回调时停止数据更新。切换实时模式后，普通页面读取、原五分钟入库任务和晨报预扫均不再轮询发现 Emby 入库。每日兜底和用户主动强制刷新仍允许查询 Emby。页面 SSE 和本服务版本查询仅同步 StrimKeep 已确认的数据，属于页面通知，不是 Emby 片库轮询。

## 实现行为

| 入口/页面 | 行为 |
| --- | --- |
| Emby 回调 | JSON、data 表单或 multipart；令牌校验，正文最多 256 KiB；持久化后应答 |
| 增量处理 | 两秒合并同一条目；单后台线程、最多 512 个待处理条目；精准 Item ID 查询、涉及作品的分集查询，不全库枚举 |
| 媒体总览 | 片库健康和作品数引用共享事实；STRM 数量按受影响目录真实文件计数，24 小时近期入库窗口本地过期 |
| 影视探索 | 从共享事实修订投影入库角标及集数，无额外五分钟远端索引扫描；海报缓存保持 |
| 片库映射 | 局部修补当前作品；入库事实先保存并发布，再单作品 TMDB 对照。另一库仍有数据时保留作品 |
| 追更通知 | 只交给已有剧集订阅规则，不自动创建订阅；通知投递沿用持久化队列，不等待 Telegram 网络 |
| 全量兜底 | 以持久化成功时间判断到期，重启不会重新启动五分钟入库发现；失败保留上一份事实 |

回调只是变化提示，不能授权删除媒体。当前 Emby 查询结果优先于事件先后；晚到的删除回调遇到已重新入库的条目，不会撤掉其当前事实。跨库电影/剧集仍遵循名称、年份和 TMDB 的严格身份合并。

未能确认的单剧身份、截断结果、路径不匹配、挂载不可见或存储异常会保留旧数据及待处理任务。失败重试退避至最多五分钟，最多 4096 个近期条目保留路径/剧集身份线索。删除回调没有 SeriesId 且无法恢复身份时等待完整校准，不猜作品。Emby 未发送的事件、某些目录批量操作、仅文件变化但尚未进入 Emby、超过有界查询上限的作品仍依赖全量兜底。

队列满返回 503。不能保证每个 Emby 插件都会自动重试；须结合回调状态、服务日志和全量兜底观察。不宣称网络回调瞬时或必达；通常在合并窗口和精准读取结束后同步，首次初始化、外部服务慢、批量入库会延后。若要停用同步，关闭入库监控；更换令牌后需要同步更新 Emby 地址。

## 验证边界

自动测试使用临时文件、真实 SQLite 和 HTTP 路由、模拟 Emby/TMDB 返回。覆盖新增/删除/跨库保留/路径移动、乱序/重复回调、队列持久化/代际保护/退避、异常保留旧事实、TMDB 失败仍同步入库、目录计数、表单格式和鉴权、禁用隐式轮询。原完整 Python、前端、静态与发布校验一并运行。

不连接生产 Emby，不操作 NAS 或媒体。本环境不能完成 Docker 构建、真实 Emby 插件回调或飞牛运行验收；安装后仍需按上面的实际入库步骤验证网络、权限及挂载。完整校验日志随补丁包提供。
