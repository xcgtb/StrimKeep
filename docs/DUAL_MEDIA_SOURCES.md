# 上游与自建 STRM 同时接入

本次基于 v1.6.4，修改尚未发布。保持现有 Docker 挂载，不移动旧库、不用新目录替换旧挂载。

| 来源 | StrimKeep 容器目录 | 配置来源 |
| --- | --- | --- |
| 上游个人库 | /media/local | 原有本地 STRM 挂载 |
| 上游分享库 | /media/share | 原有分享 STRM 挂载 |
| 自建个人库 | 默认 /strm/local | STRM 输出设置 output_root |
| 自建分享库 | 默认 /strm/share | STRM 输出设置 share_output_root |

`./strm:/strm` 挂载继续与上游两项挂载并存。不要为了让总览统计自建文件，将上游目录改绑到自建库，或给同一目录复制出第二套引用。

## 更新后设置

1. 在「连接与设置 → Emby 媒体服务」保留原上游两库路径，另填「Emby 中的自建个人库路径」与「Emby 中的自建分享库路径」。填写 Emby 容器实际看到的路径；它可能与 StrimKeep 容器路径不同。如果 Emby 尚未挂载自建 STRM 的宿主目录，先在 Emby 的部署配置中添加挂载，再填写实际可见路径。不要凭 NAS 路径或示例猜测。
2. 全局映射用于片库分类、严格删除路径核验和删除通知。各账号的 Emby 入库连接仍负责生成后的扫描及回执；如果同一服务器承担两项用途，确保对应自建路径一致。反代识别路径仍用于播放定位，不代替全局片库映射。
3. 确认四个目录的挂载正确后，在媒体总览点击「刷新总览」，完整核验当前挂载并重建统计。提示挂载身份变化时先核对挂载，不能以空目录冒充旧库。
4. 保存新 Emby 路径后，在片库映射点击「同步 Emby 片库」，更新已入库事实。作品和已入库单集来自 Emby，STRM 文件数来自 NAS，两者不是同一指标。
5. 需要自建库参与治理时，再明确开启「治理联动处理本项目生成的源文件」。只显示自建统计不会开启远端删除；实际清理仍先扫描、预览并确认。已开启的设置会保留。

## 统计与清理边界

- 总览分别显示上游、自建两套个人/分享引用数量，再汇总为个人/分享数量。相同实际文件（含硬链接及挂载别名）只计一次，不按 URL 文本合并不同文件。
- 未创建或未挂载且从未核验的新输出显示「待核验」。曾经核验过的来源消失、扫描失败或挂载身份改变时保留旧统计，不归零。
- 自建 STRM 参与磁盘元数据及季集兜底、NAS 搜片、追更兜底；Emby 未收录的文件不会因此冒充已入库。
- 上游个人库沿用原源文件联动链；自建个人库使用登记的 UID、文件 ID、指纹及持久步骤，不按旧 CD2 路径猜测。分享库只清理 NAS 引用。
- 单作品删除可能涵盖同一库类型下的两套来源，预览会显示来源数量。查看范围后再确认。未启用或未登记的自建个人引用不能进入路径兜底删除。
- 目录残留/空目录清理等独立旧工具不因新增只读来源自动扩大写入范围。本次不会迁移、重写或清理现有媒体文件。

测试证据见 dev/acceptance-dual-media-sources.md。真实 NAS 的 Emby 可见性和挂载权限仍需按实际部署核验。
