# 删除与数据同步修复（2026-10-13）

基线：main / `02bc56d310f93bde6718b003f4083c366093f737`，最近发布标签 `v1.2.4`。本修复属于未发布修改，不新打版本标签，不改已有标签或 Web 版本展示规则。

## 修复内容

1. 单剧删除和批量剧集删除共用作品身份核验：精确查询关联 Emby ID，跨成员要求 TMDB、片名和年份一致；分集还须具有可信 SeriesId、严格库归属和对应剧目录。读取失败、列表截断、混入其他剧、身份与目录冲突都返回不能核实，不继续删除。单成员缺少 TMDB 时仍允许按精确 Emby 身份核实。
2. 剧集删除和手动同步按完整双库成员重算实际存在的分集，维护存活主 ID、成员与路径，另一库仍有文件时保留海报、分库集数和并集集数。切换主 ID 时继续保留该作品的手动完结标记。
3. 电影删除后精确重建存活 ID 与路径，采用仍存在的成员作为主 ID，后续剩余库回调不再查询已删除成员。部分文件删除后也修补实际存活事实；界面使用服务端返回的新成员信息。
4. 删除后的映射、派生总览和健康快照在 SQLite 中一起提交，成功后发布页面版本事件；缓存写入失败不发布虚假的更新，并保持之前的快照。若核实过程中其他任务更新了片库，拒绝用旧状态覆盖新数据。已执行文件删除但缓存同步失败时，界面明确区分这两个结果。
5. 无 Key、TMDB 请求部分失败或结构无效时保留上次成功对照时间，保留旧有效对照元数据；没有成功记录时成功时间保持 0。Emby 事实、尝试时间和完整对照时间分别维护。轮询与回调模式对照完成后都发布页面更新事件。
6. 两种模式的慢对照遇到并发删除/入库时只向最新事实合并元数据，不恢复旧作品列表；对照过程中新增未查过的作品时不推进完整成功时间。

七维质量比较、源文件匹配置信度、源文件删除成功后才删除本地 STRM 的执行链保持原有规则。分享库仍不联动源文件。无需改 Compose 挂载或重新填写服务设置。
