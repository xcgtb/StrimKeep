# StrimKeep 0.5.2 · 精简历史分类处理

## 原因与改动

任务 #13 的只读诊断确认：它是历史动画电影分类迁移，清单尚未建立、没有文件条目，现已取消。历史受管记录中两份旧文件已不存在于正常网盘；详情接口仍返回它们的元数据，其中一份父目录为 0，旧迁移未先区分存续状态便校验历史父目录，因此停止。现存 2160p 文件的记录与云端父目录一致。这组证据不代表所有正常整理场景已在真实 NAS 通过。

按用户选择，不再维护一次性迁移功能：移除媒体库维护中的入口、创建接口与专用执行代码。旧数据库中的此类任务若继续或恢复执行，只标记停用，保留记录和已有步骤，不读取或修改云端。普通整理继续把动画电影归入电影的地区分类，动画剧集仍归入动漫并保留季目录。其他整理、同步、定时、洗版和清理逻辑不变。

## 更新命令

解压新包后运行，仍更新最初的实际部署目录：

```bash
cd '/path/to/StrimKeep-v0.5.2-simplify/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

沿用原 .env、数据、STRM、密钥和配置。脚本只从旧程序目录清除已停用的 migration.py；不自动清理数据库历史、云端文件或本地媒体。

## 验证顺序

1. 打开原 9000 管理入口，确认版本 0.5.2，媒体库维护不再出现历史动画电影迁移按钮。#13 保持已取消即可。
2. 将需要修正的一部旧动画电影手动移回待整理/转存目录，执行正常“扫描整理”。海底总动员应进入电影/欧美电影；其他地区动画电影进入电影/其他电影，动画剧集仍进入动漫。
3. 核对云端保留版本、新 STRM 和实际播放后，手动清理该作品对应旧错误路径的 STRM。此包不添加历史 STRM 搬迁或全库清理脚本。
4. 小范围 STRM 同步连续执行两次；第二次无变化不新增播放映射、不重复通知 Emby。之后再验证各自的定时扫描整理和定时同步。

本地后端 276 项、前端 7 项测试及 TypeScript/Vite 构建通过，更新脚本语法与模拟覆盖通过；详细结果见 IMPLEMENTATION_STATUS.md。没有直连 NAS 或真实 115 账号；实际整理、Emby 入库与播放仍以更新后的实测为准。
