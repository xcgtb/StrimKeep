# StrimKeep 0.6.4

基于 0.6.3 的完整源码与已编译前端。此次集中修改 Emby 实际连接通道和 Compose 输出，不调整媒体总览的数据来源或其他界面结构。

## Emby 的连接行为

Emby 使用独立 HTTP 连接池，检查连接、总览数量、正在观看、最近入库、海报、定向入库通知和入库核对均经过相同通道。同机地址绕过全局服务代理与环境代理。远程 Emby 仍可按已有代理开关使用配置的代理。

只在确认所填 IP 属于当前网络命名空间的本机接口时，如果 LAN 地址发生连接错误或超时，才尝试相同协议、相同端口的 127.0.0.1 地址。不猜测其他服务器、不尝试其他端口、不降低 HTTPS 校验。HTTP 401/403 不通过换地址掩盖密钥错误；非本机服务器不会向回环地址发送密钥。

连接成功后，将有效 API 地址与当前填写地址、密钥绑定缓存，原始服务地址不被改写。后续总览、海报和入库通知使用已确认的同一地址。已记录服务器 ID 时，回环响应属于另一台 Emby 会被拒绝。检查仍兼容 `/emby` 与根路径 API。

## YAML 按参考图固定排版

顺序固定为 image → build → container_name → network_mode → environment → volumes → restart。使用列表式 `- TZ=Asia/Shanghai`、`- ADMIN_USERNAME=...`、`- ADMIN_PASSWORD=...`。普通值不再全部加引号。

移除 Docker 解析自动出现的 `command: null`、`entrypoint: null`。Compose 修订已恢复 `init: true` 和原日志轮转配置（json-file，10m，3 份），保留在 restart 后方。更新也会补回上一份 0.6.4 中缺失的这两项。显式自定义命令、入口、日志、自定义挂载参数等仍保留。空数组命令的语义不同于 null，不会误删。真实挂载、管理员配置和其他自定义参数从原部署解析，不要求重填变量。

新安装依旧从本地源码构建镜像，因此比参考镜像部署多一行 `build: .`。无需虚构远程镜像仓库。

## 更新

将 StrimKeep-v0.6.4-composefix.zip 上传至 /vol1/1000/测试，再执行 README 的 update.sh 命令。不要删除原项目、data 或 strm，不要用新安装空密码模板直接覆盖原部署配置。更新保留账号、连接密钥、数据库、Token 和目录挂载。

0.6.3 已将本地输出目录名改为“影视媒体库”。如 Emby 媒体库选择了旧子路径，需使用 `/strimkeep/影视媒体库/电影` 或对应剧集目录；这属于文件挂载路径，和 Emby API 连接是独立设置。

## 验证

增加实际本地 TCP/HTTP 服务回归：旧共享路由因代理不可达而失败时，新 Emby 通道仍能连接；本机接口不可达时转入回环后能读取媒体数量并发送更新；Web 检查、总览和手动刷新使用同一路径；缓存不会复用其他服务器身份，远程失败不会向本机发送密钥。并执行完整后端回归、前端测试和构建。

更新脚本经模拟 Docker 配置核对，保留特殊字符密码、真实目录、密钥、STRM、自定义配置。当前执行环境无法直连用户实际 NAS，测试通过不等于已现场确认 NAS 网络恢复。
