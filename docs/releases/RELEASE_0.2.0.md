# 0.2.0 实现边界与恢复

2026-10-23，V1.1 的第二阶段。本次新增实际云端整理，不再以平铺 STRM 样例作为业务闭环。

## 识别与命名

全量递归扫描指定的待整理目录，分页完整核实、按文件 ID 去重，完整清单持久化后才修改文件。待整理根目录可嵌套；归档、待处理与扫描范围不能互相包含。后台与播放取链共享单一 115 请求锁，云端修改串行。

原名提供作品、年份、明确 SxxExx 季集和发布字段。名称/可核实的 TMDB 别名、年份必须唯一匹配，不能按搜索排名选第一项。原名可指定 TMDB ID。详情必须有作品名称、年份，剧集单集详情必须核实季集。裸数字集号、无法可靠映射的特殊篇等转待处理。

FFprobe 必须成功取得有效视频流、尺寸、编码。可信探测优先于原名；未知动态范围不写 SDR，缺失来源、平台、发布组省略，原扩展名保留。源名称与计划长期保存。目录名称过长时规范化，保留年份和 TMDB ID；文件名无法完整保留必要字段时不截断季集硬归档，转待处理。原始帧率有理数与显示值同时记录。

自动创建 7 个类型和 28 个地区目录。基础类型线索覆盖电影、分集节目、动画、儿童、纪录片、综艺；儿童优先于动画。跨地区合拍不能判断主要制作地区时保留原名待处理；多个制作国家都属于同一区域时可归入该区域。音乐电影不单凭音乐类型认定为演唱会。复杂类型/地区规则属于后续分类验收。

地区实现为源码中的明确 ISO 国家代码集合：CN/HK/MO/TW 为国产，JP/KR 为日韩，欧美使用 WESTERN 集合，其余为其他。这是本阶段实现映射，不代表完整地区边界已验收。

视频按类型/地区/作品归档，分集节目自动创建 Season。明确的 S00Exx 使用 Season 0；明确合并集保留为一个文件，核实所有涉及单集。

## 文件修改与恢复

每次修改前持久化动作意图，随后按文件 ID、大小、名称、父目录读回核实。目录 ID 必须真实存在且仍在选定范围。SDK 移动明确请求 keep_both，避免其默认同名覆盖；同时应用层检查重名、同集和意外返回名称，不执行覆盖或删除。

同电影目录有旧视频、同季有重叠集号，或已有视频无法可靠识别时，新资源保持原名转入待处理/源文件ID 子目录，旧视频不动。不具备完整归档索引，不会对现有整库执行洗版。

源名称、大小、父目录有外部变更时暂停核查。超时不直接重发：已完成的动作补记，确认未成功才按 Web 次数/间隔重试。读回失败、结果不明、磁盘记录失败均停止新修改。重启从持久化意图核查恢复，不从头重复移动。手动暂停不因重登自动恢复；取消停止后续动作，不回滚已归档文件。

单实例 Worker 使用持久化顺序。本版只允许一个未完成扫描任务；尚未开放扫描与完整 STRM 同步等多种任务的混合 FIFO 队列。

## 字幕与本地输出

同一目录、同视频主体名并附语言/简繁/forced 等后缀的 SRT/ASS/SSA/VTT/SUB/IDX 与视频关联，保持标记，随视频重命名移动。匹配歧义不猜测，记录提示。云端字幕移动失败保留步骤等待核查；下载失败标为部分完成。

视频和字幕归档核实后，才在独立的 `StrimKeep媒体库` 前缀下镜像云端分类结构。写入 tvshow.nfo、单集或电影 NFO、技术参数、长期 Token STRM，下载可取得的 TMDB 海报、背景图及外挂字幕。原子替换本地文件，播放 Token 在步骤计划中加密保存。

“补齐已归档输出”核实已归档状态后补写本地文件，不重复发送已完成的改名/移动。图片或字幕下载失败可用该操作补试。补齐不会重发本批次已尝试过的 Emby 通知；完成后使用手动扫描按钮。

批次有成功输出才通知 Emby 一次。请求前持久化发送状态，结果不明/失败不自动重试，重启也不重复通知。被接受不等于 Emby 实际入库；NFO 和图片是否被本机 Emby 版本读取需验收。
