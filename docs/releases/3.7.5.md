# StrimKeep 3.7.5

## 资源来源

- 影视探索新增 **Prowlarr** 来源。Prowlarr 内部配置 TTD 等索引器，StrimKeep 只调用 `/api/v1/search`，不再需要为每个站点单独适配。
- Prowlarr API Key 与其它设置一样加密保存；设置页只显示“已保存”，留空保存会保留原 Key。
- Prowlarr 结果只接收磁力链接，`.torrent` 和普通网页地址不会误提交到 115 离线。
- 探索搜索会把年份一起传给 Prowlarr，减少同名作品干扰。

## 追更订阅

- 新增独立「追更订阅」页面，支持全部 / 追更中 / 待核查 / 已入库筛选，以及重试、暂停、恢复、取消订阅。
- 订阅进入 `review`、`error` 或 `completed` 后重新保存，会清理旧的提交占用并重新排队；新增 `POST /api/v1/explore/subscriptions/.../retry` 手动重试。
- 订阅状态变化会写入现有通知队列，按事件去重，避免每轮检查重复推送。
- 旧收件箱里失败、跳过、待核查的同链接会在订阅重试时重新激活，而不是永久卡住。
- 取消订阅会同时清理提交记录，避免残留唯一键阻止以后重新添加。

## 收件箱与 RSS

- 收件箱新增 `processing` 状态和 300 秒租约。Worker 异常退出后，过期任务会自动回到待处理，不会永远卡住。
- 入队中或处理中的条目禁止重试、跳过、删除，接口返回 409，避免重复提交。
- 清理旧收件箱记录时，跳过仍被订阅提交记录引用的行。
- RSS 拉取改为流式读取，最多 2MB；手动校验每一跳重定向，禁止 localhost、回环、链路本地和云元数据地址。
- 重复添加同一个 RSS 地址返回 409。
- Webhook 令牌重新生成后，旧令牌保留 24 小时，给外部发送方留出切换时间。

## 频道监控

- 首次接入按 `history_pages` 实际回溯 1–20 页，而不是只读一页。
- 离线提交结果不确定时，把链接写入收件箱 `needs_review`，避免只发通知却丢失资源。
- 删除频道时同步清理分享尝试和取消记录。
- 通知任务异常会被读取并记录，不再产生未处理的任务异常。

## 健康检查

- 115 健康状态使用 `cloud_verified_at`：只有最近 24 小时内实际验证过连接才显示正常；仅配置 Cookie 时提示“尚未验证”。
- 连接测试和扫码登录成功会刷新验证时间；修改 Cookie 会清除旧验证状态。

## 升级说明

- 版本号：`3.7.5`。
- 数据库会自动补充收件箱租约列和订阅字段，无需手工迁移。
- 已有 PanSou、Telegram 来源和订阅配置保持不变；Prowlarr 需要在「系统设置 → 资源来源」中新增并填写服务地址与 API Key。
