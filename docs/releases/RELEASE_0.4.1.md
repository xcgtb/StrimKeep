# 0.4.1：按参考图调整，简化洗版设置

2026-10-23。沿用第四阶段整理与回收流程，本轮按用户最新要求收敛设置，不进入第五阶段。

## 当前设置

洗版仅九项，按默认显示顺序为：发布组、资源类型与平台、分辨率、动态范围、帧率、色深、音频规格、视频编码、文件大小。每项可独立启停、展开/收起、上下移动；桌面还可拖动规则手柄。启用顺序显示在顶部摘要；上方搜索可按名称或平台筛选规则。保存按钮固定在页面上方，显示未保存状态。

各项内部使用明确的先后顺序，不提供“并列”或“拆分”。文字选项以可读名称显示；选择、上移/下移、移除或重新添加，代替逗号填写。发布组逐个添加，按原名末尾明确的发布组匹配，忽略大小写；不支持自定义正则。

数值项默认沿用较大/较小优先；分辨率、帧率、色深也可点击“自定义各规格顺序”采用逐项列表。文件大小保持大小方向。列表中未出现的值、未知参数不能跳到后面的大小规则，转待处理。建议顺序只是可编辑预设，不代表任何平台、编码或发布组的绝对画质。启用一项空文字规则时会填入建议顺序供编辑；初始不会自动启用任何规则，发布组没有隐式预设。

资源类型支持 UHD Remux、Blu-ray Remux、UHD Blu-ray、Blu-ray、按明确标记细分的 WEB-DL 平台、WEBRip、HDTV、DVD。WEB-DL 各平台可和其他类型放在同一列表里比较；“未标注/未识别平台”只适用于已确认是 WEB-DL 的资源，不能把未知资源类型当作低优先级。多个冲突平台标记转待处理。旧平台独立偏好可原样显示和调整，点击“改用建议顺序”才切换统一列表。

音频使用探测中可核实的编码/profile 与声道，不依据文件名声称 Atmos/DTS:X 或 HDR Vivid。动态范围可按明确的 DoVi Profile 设置顺序。2560×1440 修正为 1440p 档，不再按 1080p 比较。其他实测、未知字段和回收保护沿用此前实现。

## 多版本只留杜比 / 非杜比

只有一个开关：“杜比 / 非杜比共存”。杜比指杜比视界 DoVi；非杜比包括 HDR10+、HDR10、HLG、SDR。打开后两类分别保留，各类内部依洗版规则比较；关闭后一起比较。动态范围未知时转待处理。只在允许洗版模式参与分组。

新设置不再提供修订版本、分辨率共存、帧率共存、三类动态范围共存、规格季目录或 ISO 控件。新输出用标准 Season，版本区别写入文件名。仍不写 NFO/图片。

## 兼容已有数据

不修改数据库结构，不重建或清空数据。0.3.1 的 Cookie 传输修复、旧 Token、原账号、目录与挂载保留。

新设置和新任务只使用九项规则及杜比/非杜比开关。正在执行及历史任务的配置快照不重写：原先已落盘的规则和回收意图继续按原记录核查，避免中途中断恢复时换规则。为兼容旧任务，后台保留只供旧快照解析的字段；新配置接口会拒绝提交已移除的选项。

若原配置启用了本轮移除的规则或共存方式，新任务先回到“转待处理”，请检查九项规则再明确选择模式并保存；不会在移除旧维度后静默开启淘汰。旧规格目录不会自动搬迁，Emby 原路径保持不变。

## 更新与验证

等当前任务结束，解压到 `/path/to/StrimKeep-v0.4.1-quality-ui`：

```bash
cd '/path/to/StrimKeep-v0.4.1-quality-ui/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

打开原 9000 管理入口，页面应显示 0.4.1；如浏览器仍显示旧页面，刷新后再检查。不用改 Emby 引用路径。

1. 到洗版管理确认九项规则和一个共存开关；初次升级默认冲突待处理。只读检查回收站。
2. 移动一项规则和内部一项选项，保存并刷新核实顺序保留。只要还未保存，摘要反映当前编辑内容，新任务仍使用最后保存的配置。
3. 先用测试副本只启用分辨率，确认同分待处理；不同实际分辨率按设置保留更优者。若自定义将 1080p 放 2160p 前面，应确实按该偏好比较，而非默认更大获胜。
4. 开启杜比/非杜比共存，用同片/同集的两类测试副本，确认分别保留；动态范围未知不得淘汰已有版。
5. 继续验证真实回收、更优/更差、字幕、Token、暂停/重启恢复，以及 Emby/Senplay 的实际入库、版本选择和播放。通知已接受不能代替播放验收。
