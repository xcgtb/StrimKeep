# StrimKeep 0.5.0 · 第五阶段包

2026-10-24（北京时间）。用户已确认上一阶段洗版测试通过；本包在该基线上推进 V1.1 第五阶段，并处理约定的三项分类与性能优化。NAS/115/Emby 的本轮结果仍以更新后的实测为准。

## 更新

解压后，在新包目录执行；参数仍是原项目，沿用已有数据和 Token：

```bash
cd '/path/to/StrimKeep-v0.5.0-phase5/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

更新完成打开原 9000 管理入口。包内有编译后的前端，飞牛无需运行 npm。更新脚本只构建/更新 strimkeep；保留原 .env、数据/STRM 挂载、master.key、Cookie、播放 Token 及任务记录，不操作 Emby/ 容器。新增表为兼容性扩展，不自动备份或重建数据库。

## 三项改动

1. **动画电影分类**：先区分电影和剧集；动画电影进入“电影/国产电影、欧美电影、日韩电影、其他电影”。动画剧集继续使用动漫与 Season。不增加动画电影子分类。“归档索引 → 修正已归档动画电影”可迁移本工具已记录的错误分类，更新云端目录、受管 STRM 与绑定字幕路径，并保留文件 ID/播放 Token。旧 NFO/图片与用户文件保留。
2. **本地归档索引优先**：首次建立完整索引，之后整理使用本地索引找相关作品、核实对应目录和候选文件，修改成功后更新记录。手动完整刷新保留；“系统设置”可配置完整复核小时数，默认 0，仅手动刷新。无需每次遍历整个 115 归档。外部工具改变无关作品不会即时推送到本地，须手动刷新或启用周期复核。
3. **复用实际探测结果**：保存完整 FFprobe 参数与原始名称。账号、文件 ID、合法 SHA1 和精确字节数一致且所需参数齐全时，洗版复用缓存；否则才取链重探。发布组、资源类型与平台仍由原名判断。不会把未知值当低质量，也不把文件大小代替媒体身份。

## 第五阶段入口

| 页面 | 操作及行为 |
|---|---|
| STRM 同步 | 选择一个或多个 115 目录，保存后立即同步视频入口与绑定字幕。云端只读；归档内镜像到 StrimKeep媒体库，其他目录进入 StrimKeep同步。 |
| 任务队列 | 整理、同步、索引、分类修正统一 FIFO；查看总数、进度和文件步骤；暂停、核查继续、取消执行中或排队任务。 |
| 系统设置与通知 | 设置定时扫描与同步开关、间隔。定时同步目录独立选择；扫描使用已保存的整理目录。 |
| 系统设置与通知 | 站内通知与可选 Telegram Bot Token / Chat ID、测试发送、未读及历史。敏感设置加密，留空保留原值。 |
| 归档索引 | 保留手动全量刷新；增加修正已归档动画电影。 |

定时扫描/同步初始关闭，间隔单位分钟（最少 5）。触发时保存配置快照，后续设置不修改正在排队的任务。错过多个周期只补一次；相同账号、类型和目录的定时排队任务合并。当前任务运行时调度器仍可入队。队首暂停、等待登录或等待核查会保留 FIFO 位置，需继续或取消后推进后续任务。

同步保留有效 Token，支持修复缺失、改名/移动后的本地路径和播放基础地址；普通同步不会恢复已撤销 Token。完整清单且当前对象核查通过后，才清理确认失效且哈希一致的受管 STRM/字幕。文件只是移出所选目录时保留；登录、网络、分页、范围变化或歧义不授权删除。用户修改的文件、NFO、图片及未登记文件保留。字幕有歧义或下载失败会保留旧输出并提示。

有输出变化的批次结束后只尝试一次 Emby 扫描通知；无变化的同步不通知。已接受不等于入库或播放成功；失败/结果不明不自动重试。站内通知保持持久化，Telegram 不明结果同样不自动重复发送。Telegram 使用官方 [Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage)。

整理、同步和播放取链共用串行 115 API 通道，后台请求之间可处理播放请求。扫描与字幕归属按目录及名称索引，避免视频、字幕两两全库比较。

## 这次按顺序验证

1. 版本 0.5.0、115 登录正常、旧 STRM 可播放；不要重复上阶段的回收故障复现。
2. “归档索引”点“修正已归档动画电影”。海底总动员应到“电影/欧美电影”；确认 115 保留版本、对应新 STRM、旧受管路径清理、原 Token 仍可用。其他地区动画电影应进入其他电影；剧集仍为动漫/Season。
3. “STRM 同步”先选择小范围归档目录。连续同步两次，第二次无变更不新增映射、不再通知 Emby。删除一份本地 STRM 后再同步应补齐；修改播放基础地址后同步应更新地址且保留 Token。
4. 用测试副本在 115 改名/移动、删除，分别同步：改名移动更新受管路径；确认删除后清理旧受管输出。保留一份手工 NFO 和改过内容的 STRM，确认不被覆盖或清理。移出选定范围应保留本地输出。
5. 在“系统设置”选独立的定时同步测试目录，以 5 分钟间隔开启。手动任务与定时任务在“任务队列”按顺序推进；暂停/取消、重启恢复不重复修改。验收后再设置实际间隔和范围。
6. 查看站内通知；需要 Telegram 时填自己的 Token 与 Chat ID 后测试一次。最后验证 Emby 实际入库，以及 Senplay/Infuse 播放与拖动。

若需要第三方定时清空回收站，已保存的回收核查证据继续有效；尚未确认的回收意图仍不能凭“回收站为空”判成功。本包没有新增全局清空回收站任务，原 #10 单独目录恢复仍限定原任务已记录的目录，不扩大到历史空目录。
