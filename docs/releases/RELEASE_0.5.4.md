# StrimKeep 0.5.4：恢复日常自动整理

2026-10-24。基于 0.5.3，优先修复自动整理及审计发现的同类中断。本版保留串行 FIFO，不重做整体 UI，不新增人工确认、排除或放行整库步骤。

## 更新与验收

```bash
cd '/path/to/StrimKeep-v0.5.4-automation/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

沿用原 .env、配置、数据、STRM、密钥与任务。程序目录按完整包替换，移除旧模块和前端资源；请勿把个人数据或自定义代码放在 backend/strimkeep、backend/tests、frontend/src、frontend/dist、frontend/tests、docs 这些程序目录内。更新脚本拒绝直接以软链接作为待替换程序目录。

验收只需一部：把海底总动员放回已保存的转存目录，直接扫描整理，无需先盘点、清索引或维护 ID。确认电影/欧美电影的云端文件、新 STRM 与播放。再连续整理两次，核查同片冲突处理；手工删除一个空作品目录后再整理，缓存应自行重查/重建。原任务仅需目录收尾时继续使用原任务核查按钮。

## 冲突发现范围

正常整理检查本地已有记录与目标作品目录，并现场核实相关候选。目标作品目录内外部新增的视频会参与核查，不会因为全库存在一个未知视频就全部停止。

其他工具放在任意非标准目录、名称改变且未曾登记的旧资源，不能凭当前作品目标目录自动推断。需要一次可选“旧库盘点”导入，才可参与跨目录比较；不保证不盘点也能发现所有非标准旧库重复资源。不会把局部记录标成完成全库盘点。

## 尚未完成

本包不宣称审计全部清零。A-08 代表音轨一致性、C-08 通知保留策略、D-01 有序数据库迁移框架、D-02 播放优先调度、D-03 真实 115 契约烟测、D-04 路由拆分以及 D-05 并发/时钟/真实满盘覆盖仍待做。C-02 仅改善当前作品目录及已记录候选，不用每日全库扫掩盖任意旧库发现边界。C-06 保留用户确认的 FIFO 语义；暂停的队首仍需继续或取消，不绕过队首并发执行。

## 验证证据与限制

完整后端回归 284 项通过；其后增加的延迟期限恢复测试包含在 6 项专项回归中通过。前端 7 项测试、TypeScript/Vite 构建、更新脚本语法和模拟覆盖通过。模拟覆盖核对配置/运行数据不变、孤儿模块和旧资源消失、只更新 strimkeep。

针对旧测试中“自动先全量盘点”和“未知条目阻断整库”的断言按新需求修改：非标准旧库比较测试显式先导入盘点；无关未知条目应允许正常整理；移出归档的候选应自动退出归档冲突记录。原有回收唯一关联、账号隔离、覆盖保护、目录范围和分页完整性测试保留。

未直连真实 NAS、115 或 Emby，没有用本地回归冒充真实验收；本轮未重做浏览器视觉验收。没有随包提供 .env、数据库、凭据或个人密钥。
