2026-10-24（北京时间）。0.4.4 更新后，用户原任务 #10 已显示已整理 1、待处理 0、Emby 已接受扫描通知；视频处理不再卡在回收核查。批次仍“部分完成”的原因是空目录回收记录未唯一关联。新旧 STRM、云端最终名称及播放的直接验收仍需用户核查。

## 改动

- Web /rb 明确按 type=1 文件、type=2 目录解析；不复用其他接口的枚举。未知类型不猜成目录。
- 目录读回加入最多三次串行只读核查，容忍短暂可见性延迟。已保存回收意图仍不重复提交。
- 原任务“部分完成”且保存了未完成目录记录时，显示“重试空目录清理”。通过原任务 ID 入队，只读取并处理该任务已保存的目录范围。
- 该入口跳过视频整理、FFprobe、归档全量索引、源目录扫描和分类初始化；不改视频计划、Token、STRM，不再次通知 Emby。已提交的目录意图只读关联；尚未提交的相关目录仍按原范围/名称/路径/完整空状态核实后处理。已确认、非空保留和不相关目录不重复处理。
- 登录失效、暂停或重启保留“仅目录清理”模式，继续时仍限定目录工作；请求并发仍受当前任务互斥约束。
- “补齐已归档输出”继续保持云端只读，取消目录重试后再补输出不会误进入目录回收。
- 不改数据库结构。原视频回收证据、元数据/原目录检查、新版本输出核查和不确定结果停核查的保护保留。
