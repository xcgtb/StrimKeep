# StrimKeep 0.5.8：目录读取、整理失败分流与队列修复

这是基于 0.5.7 的完整源码包，包含已构建前端，保留 0.5.7 的客户端选择扫码登录及此前功能。无需逐个安装旧补丁。运行数据和真实 `.env` 不在包中。

## 本次行为

- 日常整理和洗版无需先建立完整归档索引。读取当前作品目录比较资源；本地记录作为缓存，失效后重新读取。支持当前标准分类目录、作品 TMDB 标签及同季的版本目录；非标准旧目录仍可使用可选的旧库盘点功能。
- 115 目录计数和回显 offset 不作为完整性门槛。按实际返回条目翻页至空页；真正重复页自动重新读取，持续异常只影响相关任务。目录路径缺失时使用 SDK 的当前目录属性接口，不再比较历史祖先路径快照。
- 目录名称从实际父目录内容解析。删除后重建目录、手动把资源移回待整理目录，不要求人工修复历史 ID 关联。
- 只调度可执行任务，按任务顺序串行处理。暂停、等待登录、异常任务不占队首；单文件失败继续处理其他文件。
- **未识别目录可留空**：整理前识别、探测等失败时原位保留，不改名、不移动；配置后以原名直接移入未识别目录，已绑定字幕随行，不再创建文件 ID 子目录。同名冲突或无法确认转移结果时保留文件并记录原因。可直接日常扫描，无新增“重试失败文件”流程。
- 若视频已经移动成功，后续 STRM 或字幕失败会如实保留已完成操作，不把它伪报成“从未移动”。不会回滚或重复回收。
- 分类目录按需创建。取消开始整理前创建全套分类及全局读取回收站的步骤；真正淘汰旧资源时才检查回收结果。
- 转存后等待目录可见，限次自动读取确认，成功后只创建一个后续整理任务；丢失响应时不重复提交转存。
- 播放不进入后台任务队列。播放取链使用独立连接池和请求通道，不等待后台请求完成；转存、整理与 STRM 同步继续串行运行，可手动暂停。播放器直接使用 115 直链传输视频，播放会话不占后台任务队列，也不会暂停后台。相同会话、文件和 UA 的播放地址在内存中短暂复用 15 秒，减少 HEAD/GET 与重连的重复取链。
- 空目录清理失败保留目录，不要求通过清理才能继续其他任务。本地数据、密钥、STRM 挂载不变。

仍保留实际文件读写前后的名称、内容和当前位置检查，避免误覆盖或重复回收；这些是内部实际操作检查，不要求用户维护目录身份记录。

## 覆盖现有部署

将压缩包上传到 `/vol1/1000/测试`，在 NAS SSH 中完整执行：

```bash
cd "/vol1/1000/测试" &&
unzip -oq "StrimKeep-v0.5.8-flowfix.zip" -d "StrimKeep-v0.5.8-flowfix" &&
bash "/path/to/StrimKeep-v0.5.8-flowfix/StrimKeep/update.sh" "/path/to/StrimKeep"
```

最后一个路径是现有项目目录。更新脚本替换程序、构建镜像并重建容器，保留现有 `.env` 和数据挂载。**不删除 `data`、`strm`，不执行 `down -v`，无需重建索引。**

确认启动：

```bash
cd "/path/to/StrimKeep" &&
docker compose ps &&
docker compose logs --tail=80 strimkeep
```

页面刷新后版本应为 `0.5.8`。新安装运行 `bash start.sh`，默认数据与输出目录为项目下的 `data`、`strm`；覆盖安装沿用已有配置。

## NAS 上的简短验证

1. 不点“旧库盘点”，放一个正常资源到待整理目录，立即整理；应自动归档并生成 STRM。
2. 未识别目录留空，用一个无法识别的测试文件和一个正常资源一起整理：前者原名留在源目录，后者继续成功。再配置未识别目录，用另一测试文件确认直接原名移入该目录。
3. 把一个归档资源手动移回待整理目录再整理，或删除空作品目录后重新创建同名目录：不应要求修复目录 ID 或完整索引。
4. 暂停一个任务后新建任务，后者应继续执行。TG 转存并开启整理接续时，应在保存确认后自动出现整理任务。
5. 后台整理期间打开已有 STRM：播放取链不应等待后台任务完成，后台仍继续；再测试更优资源洗版，确认新输出和旧资源回收结果。

代码回归和本地模拟验证不替代实际 115 账号与 NAS 网络验收；不宣称已完成真实云端洗版和播放器解码测试。
