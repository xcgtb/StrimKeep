# StrimKeep 0.6.3

完整源码发布包，包含已编译前端、锁定依赖和全部后端。可直接覆盖升级 0.6.2 或更早的现有部署，不是只含差异的补丁。

## 未识别资源保留原结构

未配置未识别目录：失败资源原位保留，不改名、不移动。

配置后：先完成同批能识别的资源，再将剩余失败资源所在的原始发布目录整体移入未识别目录。原目录名、子目录、视频、字幕、海报、NFO 及其他附属文件随目录保留，不拆成裸视频，也不清理失败资源目录。来源根目录里的散装视频保留原名与关联字幕直接转入。若目标有同名目录，不合并、不生成带后缀的新名，原位保留并记录日志。移动意图先持久化，再按目录 ID 核实结果，不重复提交不确定的目录移动。

例如：`待整理/原发布目录/Season 01/未知视频.mkv` → `未识别/原发布目录/Season 01/未知视频.mkv`。`原发布目录` 中其他附属文件一并保留。

## 目录与手机布局

手机只展示面包屑、返回上级、单文件列表，刷新作用于当前目录；文件夹不显示空大小列。桌面保留左树右列表，树按需读取并虚拟渲染，固定行高与虚拟列表一致。快速切换时，旧请求不再覆盖新目录的路径、内容与选中项。文件夹选择弹窗使用同一套列表与请求序号保护。

保存按钮回到文档流，不悬浮覆盖表单；统一页面底色与最小高度，移除无背景图时的固定背景层和强制合成设置。实际 iOS Safari 的底部细线仍需在设备上复核。

## Emby 连接与媒体总览

“检查连接”使用页面当前填写的地址和密钥，密钥留空时使用已保存密钥；测试不会偷偷保存草稿。兼容 `/emby` 和根路径 API，成功解析的路径也用于后续定向入库通知。错误区分 HTTP 状态、超时、连接失败和非服务响应。Emby 代理只作用于已配置的 Emby 主机，不再影响其他请求。

媒体总览的数量、最近入库和正在观看只来自 Emby。读取失败明确显示原因；同一配置已有成功数据时显示带提示的上次 Emby 数据，切换配置后不复用旧服务器数据，不以本地记录代替 Emby。

## Compose 与媒体库名称

默认 Compose 不使用 `${变量}`，管理员账号与密码直写 YAML，数据和 STRM 默认为项目下 `data`、`strm`。管理员环境配置仅首次初始化生效，更新不重置既有登录。`start.sh` 不再交互索要变量。

更新脚本读取旧 Compose 的解析结果，保留已有账号配置、自定义参数和真实挂载路径，转换成直写配置。真实部署文件权限设为 0600，并从 Docker 构建上下文排除；保留旧 `.env`、数据库、加密密钥、Token 和文件。不要把新包里的空密码模板直接盖掉原部署文件，请运行 `update.sh`。

本地 `StrimKeep媒体库` 自动更名为 `影视媒体库`，本地路径记录同步更新，播放 Token 保留。新旧同名空间都已有内容时保留两边，不强行覆盖。迁移后的首次相关同步会通知 Emby 新旧路径变化。

**Emby 的宿主机挂载仍为 `/path/to/StrimKeep/strm:/strimkeep:ro`，程序映射仍为 `/strm` → `/strimkeep`。如果媒体库选择了旧子路径，须把 `/strimkeep/StrimKeep媒体库/电影` 改为 `/strimkeep/影视媒体库/电影`；剧集同理。**本包不远程修改用户的 Emby 媒体库设置，不触发全库扫描回退。

## 验证范围

执行后端回归、前端测试与生产构建；模拟服务验证 Emby 根路径、当前表单检查、错误展示、上次 Emby 数据标识、配置切换隔离、目录移动及 Token 保留。浏览器验证手机单列表、桌面目录切换乱序响应、文件夹选择及保存按钮不重叠。更新脚本通过模拟 Docker 配置验证账号、特殊字符密码和挂载保留。

本环境无法连接用户真实 NAS、115 或 Emby，也没有 Docker 守护进程；不把模拟通过表述为实际网络或播放器已连通。
