# StrimKeep 0.8.36：深度删除联动回收 115 上空出来的目录

## 一、问题

0.8.35 已让深度删除联动清理本地 STRM + 专属侧车（nfo/海报/mediainfo）并删除本地空目录，
但**网盘（115）上的源目录没删**：删掉一部电影/一季最后一集后，115 上对应的
`片名 (年) {tmdb-x}/Season 1/` 变成空目录却一直留着，越堆越脏。

## 二、改动

| 文件 | 改动 |
| --- | --- |
| `deep_delete.prune_cloud_empty_chain()`（新增） | 删完源文件后，从该文件的父目录开始**自底向上**回收 115 上变空的目录：每层先 `children` 判空（非空即停），再用 `recycle_empty_directory`（它自身还会再核位置与空目录）回收，然后处理上一级，遇到同步根/归档根即停 |
| `deep_delete.guarded_managed_delete()` | 托管真删确认回收后，若本地目录已清空（或本地 STRM 本就不在），调用 `prune_cloud_empty_chain`；结果写进返回消息（“已回收网盘空目录 N”），失败只记提示，不影响已确认的源文件删除结论 |
| `tests/test_deep_delete.py` | 新增 2 项：本地目录清空后联动回收云端目录链（遇同步根即停）；云端目录仍有内容时绝不回收 |

### 安全边界（关键）

- **只回收「同步根 / 归档根之下的空目录」**：从 `sync_config.source_cids` 与
  `organize_config.source_cids`/`archive_cid` 取根集合，`trail[:-1]` 不含任何根就直接返回，
  绝不越界删库根或根以上目录。
- **非空即停**：`children` 一有内容就返回，不删任何还有别的文件/字幕/未识别内容的目录。
- **双重核实**：`recycle_empty_directory` 自己会再核「位置未变 + 目录为空」才发一次删除请求。
- 失败（登录/限流/目录被改）只记 note，不把已确认的源文件删除改判为失败，也不重复提交。

## 四、已知边界

- 只在「本地目录已清空」时才尝试回收云端目录链（多集目录里删中间一集时本地仍有其它 STRM，会跳过云端删除尝试）。
- 只在同步/归档根之下回收；根本身与库根永不删。
- 回收失败（登录失效、限流、目录并发变化）只提示，不重试、不回滚已确认的源文件删除。
