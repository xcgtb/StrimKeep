# 0.2.1 文件身份核查修复

## 问题与修复

0.2.0 用 fs_file_skim 获取当前文件信息，该接口不保证包含 parent_id。代码将缺失的父目录与扫描记录比较，导致正常文件在识别、探测阶段停止，显示“文件身份、大小、名称或位置与操作记录不符”。

本次沿用 SDK get_attr(skim=True, ensure_parent_id=True) 所使用的 fs_supervision 接口，使用 skim 实际返回的 pickcode 补取完整身份信息。核实两次读取的文件 ID、名称、大小、SHA1 和 pickcode 一致后，使用真实父目录核对原任务。缺字段或身份变化仍然停止，不会用扫描记录填充当前状态，也不会跳过校验。

停止原因现在写入操作记录；外部改名、移动或内容变化会分别提示不一致字段。接口身份信息异常时暂停整批，不自动转移到待处理。

## 更新及继续原任务

将本包解压到 `/path/to/StrimKeep-v0.2.1-phase2`，然后：

```bash
cd '/path/to/StrimKeep-v0.2.1-phase2/StrimKeep'
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

目标参数必须指向包含正在使用的 .env 的原部署目录；此处沿用原部署路径。更新只构建、重建 StrimKeep 容器，沿用原 .env、加密密钥、SQLite、Cookie、任务和 STRM 数据。数据库结构不变。不会自动恢复 needs_review 状态的任务。

更新完成刷新页面，确认版本 0.2.1，在“扫描整理”的任务 #1 点击“核查并继续”。程序读取现有任务与远端真实状态后继续。分类目录已有则复用，已确认完成的改名和移动不会重复执行。

## 本地验证与边界

- 实际安装的 p115client SDK 加 httpx 模拟传输覆盖 skim 无父目录、supervision 补取父目录，包含大文件大小与长文件 ID。
- 回归测试覆盖原任务错误暂停后继续、已有分类目录复用、每个文件改名和移动各一次、生成 STRM。
- 缺字段、两次读取不一致和真实外部改动保持停止，停止原因写入操作记录。
- 本包继承 0.2.0 的范围，真实 115 请求和 NAS Docker 运行结果仍需部署验收。
