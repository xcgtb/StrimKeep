# 0.3.1：修复重启后 115 请求遗漏 Cookie

2026-10-23。用户实际测试：0.3.0 归档索引读取 31 个视频，31 个身份已确认、待确认 0；一批 14 个视频整理 13 个、重复 S05E13 转待处理，原版仍在；另一批 7 个视频的暂停、核查继续和整理完成通过。重启测试中任务 #6 和已完成计数保留，但 115 显示失效；重新扫码后同一任务继续。

## 原因与修复

Cookie 已加密持久化在 SQLite，不是只存在内存。实际安装的 httpx_request 0.1.9.1 在构造 HTTP 请求后才处理传入 cookies 参数，未将 SDK CookieJar 写到本次请求。扫码期间响应填充了共享 httpx 会话的内存 Cookie，后续操作因此暂时可用；进程重启后会话为空，请求没有认证 Cookie，115 返回未登录。

修复前已用真实固定版本 SDK 与 MockTransport 复现：重新打开同一数据库后 cookie 存在，但实际发出的 HTTP 请求无 Cookie，登录检查失败。

增加 SDK 请求适配：发送前根据 SDK CookieJar 的域名、路径选择 Cookie 并写入请求头，保留 SDK 请求格式与响应解析。显式 Cookie 头优先；无 SDK Cookie 的二维码请求不继承旧会话凭据。更新账号后立即使用数据库中的新 Cookie，不依赖旧 httpx 内存状态。正常登录失效仍停止任务等待登录，不忽略认证错误。

本次不修改数据库结构、115 云端文件、任务记录、播放 Token 或 Emby 挂载。没有增加自动登录或更换扫码设备。前端仍随包预编译，NAS 构建不执行 Node/npm。

## 更新与复测

先让当前测试任务结束，解压到 `/path/to/StrimKeep-v0.3.1-authfix`：

```bash
cd '/path/to/StrimKeep-v0.3.1-authfix/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

1. 确认页面版本 0.3.1，进入连接设置，先直接点“检查登录”，不要先扫码。现有 Cookie 仍被 115 接受时应直接通过。
2. 检查成功后执行 `docker restart -t 30 strimkeep`，Web 恢复后再次直接检查登录，验证新连接能使用持久化 Cookie。
3. 前两项通过后再用少量可恢复测试副本验证执行中重启：同一任务编号、已完成记录保留，剩余文件继续；无重复移动或额外副本，STRM 齐全。
4. 若仍失败，保留任务与配置，反馈检查提示和任务卡片，不提供 Cookie、密钥或播放链接。远端真实退出、同设备其他登录导致会话失效等情况仍可能要求重新登录，不能仅凭“Cookie 已保存”判定远端仍有效。
