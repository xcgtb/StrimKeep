# 0.9.85 库存管理与缺集监测

## 功能

- 按已登记的网盘和分享 STRM 聚合 TMDB 作品，查看海报、各库文件数量与各季已播缺集；手动完结只改变标记，不改写缺集事实。
- 跳转影视探索时带入作品身份，打开资源搜索；选定资源后仍由现有转存流程处理。
- 单库多版本与前序/中间缺口先行检查；有未处理的单库问题时不对该季做双库裁决。合并集或未知质量进入待核实。
- 质量规则沿用影视整理的启用项与顺序，不比较文件大小。电影按作品比较，剧集按季比较；仅在胜方覆盖另一方全部集号时建议保留胜方。平局保留库可配置。
- 单项或批量删除前生成清单，确认后才执行；网盘源经既有回收站回读确认，分享源只清理经过身份校验的本地 STRM。失败或快照变化时停止，计划不能自动重发。
- 提供目录与台账核对。已撤销、缺文件、无任何归属的旧网盘台账可由用户预览并确认修复，原始行随修复事务备份到数据库的 `inventory-stale-backup:` 项。

## 限制与使用

- 映射使用项目已登记且路径中包含明确 TMDB 标识的 STRM，不会把未登记文件作为可信库存。目录核对发现缺失、未登记、重复或库根不明时，治理预览与删除计划会停止。
- 映射仅把 TMDB 带有效播出日期、已经播出的正片计入应有集数；日期未知和请求失败的季单独标出。特别季 S00 不参与缺集治理。
- 未知规格不会作为平局或低质量。整理规则未启用或文件名缺少需要的规格时，应先核实规则及文件名。
- 删除是逐条执行而非跨网盘的事务；中断后可能已经完成部分文件，须先查看计划历史、回收站和库，再重新扫描。回收站保留期由 115 决定。
- 当前飞牛现场的只读核对发现一条网盘台账记录对应的 STRM 不存在，且播放已撤销、没有输出归属；用户需在库存页面核查并自行决定是否备份修复。不会自动更改。

## 回滚与验证

更新前备份数据库、密钥、compose 配置和源代码，并保留旧镜像；回滚镜像与配置前先核对正在执行的任务及删除计划。回滚软件版本不会自动恢复已经回收的网盘文件或已删除的本地 STRM。

开发验证包括隔离 STRM/SQLite 的删除计划、来源身份、故障与并发测试，以及前端构建。具体候选镜像、全量门禁与线上部署结果记录在工作日志。
