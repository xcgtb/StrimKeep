# StrimKeep 0.5.6：主链路改进

本包累计包含 0.5.5 和之前修复。沿用单容器、现有数据和后台 FIFO，不增加必须维护的文件 ID 关联，不要求每次整理前盘点。

## 这次改变

- **音轨一致**：规范命名、共存版本名和洗版比较共用代表音轨选择。启用音频规则时按该批保存的偏好，编码相同再比较声道；DTS-HD MA/HRA、LPCM 使用规范名称。未启用时用固定默认顺序。命名不再固定取第一音轨。
- **转存范围**：自动创建的整理任务只读取本次“转存任务-编号”文件夹。目标目录中之前积压或随后放入的其他文件不一起整理；本批空文件夹按原范围/空状态核查后清理。转存恢复仍不重发保存请求。
- **Emby 补偿**：最多 3 次扫描尝试，补发前先查本批具体 STRM；响应丢失但已经入库则不再补发。检查独立于整理队列，重启继续。默认每 30 秒检查，最长 30 分钟。任务页显示检查原因和确认数量，最终结果进入站内及已配置 TG 通知。确认路径须对应本批版本，不只看 TMDB。
- **同步减负**：手动同步完整核对；定时在 30 分钟内可复用近期完整清单，到期、路径变化或本程序修改云端后重新扫描。缺少/改变本地输出或播放地址时先重新读取云端再修复。完整扫描的未变化文件也跳过重复详情、路径和字幕下载查询。

缓存判断要求账号、文件 ID、有效 SHA1/大小、名称、父目录、目录链、字幕指纹、本地所有权与文件哈希一致；Token 撤销不复活。缓存轮次只核对现有输出，不据旧清单删除文件。手动完整核对仍保留逐目标修改前核查和确认失效后的清理保护。

这不是 115 实时增量监听。其他客户端的新增/移动/删除在下一次完整核对时发现；最迟为下一次距上次完整核对已满 30 分钟的定时任务，仍受任务排队影响，不是每 30 分钟强制创建额外任务。定时设置若每小时执行，发现时机仍是下一小时任务。

## 覆盖更新

将完整包解压到 `/path/to/StrimKeep-v0.5.6-chainfix`，执行：

```bash
cd '/path/to/StrimKeep-v0.5.6-chainfix/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

第二个路径是最初实际运行的 Compose 目录；实际不同请替换。原配置、数据库、密钥、Token 与 STRM 挂载保持；仅更新 strimkeep。新增两个兼容表保存 Emby 交付和同步核对记录，不重建原库。旧已完成任务不会被批量重新通知 Emby；已有排队任务保留创建时配置，新建转存任务才使用本批范围规则。

## 简短验收

1. 在默认转存根目录先放一个无关视频；通过 Web/TG 保存一个小分享并自动整理。确认仅处理本次任务文件夹，无关视频原地不变。
2. 用包含不同规格音轨的样本核对文件名与洗版音频规则一致；自定义音频顺序后新任务应按新偏好选择。
3. Emby 正常连接时观察任务页由“已接受扫描”到“已确认 x/x”。临时断开 Emby，用一个样本确认自动补发恢复；即使 Emby 不可用，后续整理也能完成。不要用生产 Emby 长时间故障测试大量重复扫描。
4. 同步同一目录两次：内容未变时不应重复取详情/下载字幕。短间隔定时可复用清单；删掉一个本地受管 STRM 后再同步，应重新核对并补齐，Token 保持。
5. 在其他客户端新增一个视频：手动立即同步应发现；定时发现需等完整核对到期的那次任务。最后用实际播放器验证，不把入库检查当作播放测试。

## 边界和剩余工作

- Emby“已确认入库”表示具体 STRM 路径或对应播放映射已在媒体库条目中找到，不表示播放器已起播。接口版本、服务器权限、挂载路径不匹配可能导致未确认，输出仍保留。
- Emby 已明确接受扫描后不反复触发刷新，仅后台查询；3 次通知均未确认时停止补发，继续查到期限。配置改变不自动把旧批次发给另一 Emby 服务。
- 大批作品分组限量轮询；每轮检查时间有界，后台整理仍保持原 FIFO。等待登录/核查的队首、STRM 延迟占队列等未改变。
- 旧库任意非标准目录的资源发现、播放优先、整体 UI、通用迁移、长期归档及满盘恢复仍见 [计划对照](PLAN_REVIEW_0.5.6.md)。
- 未直连用户 NAS/真实 115、TG、Emby；受控回归和浏览器测试不代表完成真实验收。

协议依据：[Emby Items 查询](https://dev.emby.media/reference/RestAPI/ItemsService/getItems.html)、[Library/Refresh](https://dev.emby.media/reference/RestAPI/LibraryService/postLibraryRefresh.html)。
