# StrimKeep 0.6.2：前端性能、TG 入库卡片与 Emby 路径更新

完整源码包，包含后端、可维护前端源码、锁定依赖、预编译前端和更新脚本。保留上传响应式界面的导航、转存、整理、洗版、STRM、通知分类、深浅色等功能，合入本轮 Emby 入库修复。

## 输入包检查

用户提供的 `StrimKeep-0.6.0-Responsive-UI-Refresh(1).zip` 只有 19 个前端文件，是覆盖补丁。其说明明确记录未完成 Vite/vue-tsc 构建，保留旧 JS 并叠加 CSS/脚本；本轮也在源码构建中发现并修复一个缺少类型声明的事件参数。使用的是 Vue 3，但框架名称不代表正确管理页面生命周期或控制渲染开销。

## 性能修改

- 使用 Vue KeepAlive 管理当前页面，不再将访问过的页面全部挂在 DOM 中用 v-show 隐藏。表单草稿和页面状态继续保留。
- 页面失活、浏览器进入后台时停止计时器和 EventSource；恢复可见后再接续，离开日志页不会持续拉日志。
- 任务实时推送正常时停止额外 REST 轮询，断线才用轮询补充；有打开的详情时按需刷新详情。推送中未变化的任务复用原对象，避免整批重绘。
- 日志采用固定窗口渲染，最多 22 行节点；搜索延迟合并、事件按动画帧合并、浅层响应数据。完整文本点击查看，并保留载入更早日志。
- 网盘树使用虚拟树，只渲染可见节点；每次读取一页，更多目录按需加载，避免展开一个目录时拉完全部分页。
- 业务页面按路由分包，Element Plus 仅注册实际使用组件和样式；重复并发 GET 合并，不缓存写操作或明文密钥。
- 删除交付用独立脚本给旧包打补丁的方式，全部功能从 Vue/TypeScript 源码重新编译。静态文件启用 Gzip；API 和 SSE 不经过静态压缩中间件。

## TG 卡片

参照用户提供的卡片：横向背景图优先，标题同一行展示“新片入库：作品名（年份）”，剧集下一行展示季集范围，然后依次显示来源、分类、版本、文件数、本季集数（有可靠数据时）、体积、影号、组名和结尾文案。

版本使用 WEB-DL / BLURAY、DoVi / HDR / SDR、分辨率等简洁信息；不显示原始 hevc、HDR PQ 或“未知”。未确认的 HDR 不伪造为 HDR10。电影不显示“本季”，缺失的组名显示横线。多集连播文件保持实际文件数量；不连续集号分别列出。

卡片不再展示本地 STRM 路径、任务编号或 Emby 扫描等待状态。这些信息仍在日志与独立通知分类中可查。通知分类开关和原有选择保留；若只需要海报卡片，可关闭 STRM 汇总、文件明细和 Emby 检查通知。不会擅自覆盖已有通知偏好。

## Emby 优化

仅提交本批新增、改名、删除和字幕变化的具体路径，取消接口报错或仅删除时自动回退全库扫描。首次约 3 秒后核对入库，前两分钟每 10 秒检查，之后每 30 秒。日志记录映射后的路径、接口响应及“通知到核对确认”耗时。

Emby 内部仍可能合并等待、检查父目录和抓取元数据，不能承诺固定几秒入库。本工具不自动调用全库扫描作为兜底；显式手动全库扫描接口保留。

## 更新

将压缩包上传至 `/vol1/1000/测试`：

```bash
cd "/vol1/1000/测试" &&
unzip -oq "StrimKeep-v0.6.2-ui-tgfix.zip" -d "StrimKeep-v0.6.2-ui-tgfix" &&
bash "/path/to/StrimKeep-v0.6.2-ui-tgfix/StrimKeep/update.sh" "/path/to/StrimKeep"
```

沿用 `.env`、data、strm、数据库、密钥和播放 Token。刷新确认 0.6.2。可直接覆盖 0.5.8、0.6.0 及其前端覆盖补丁版本，无需先安装 0.6.1。
