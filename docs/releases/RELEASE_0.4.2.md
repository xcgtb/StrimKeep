# 0.4.2：完全相同的新副本直接回收

2026-10-23。按用户要求，允许洗版时增加内容重复判定，避免完全相同的复制件再次进入待处理；保留 0.4.1 九项规则及杜比/非杜比共存页面。

## 判定与结果

需同时满足：同一媒体类型及 TMDB 身份；剧集季号和完整集数范围一致；文件 ID 不同；两次实时文件详情中 SHA1 为合法 40 位十六进制且一致，精确字节数一致且大于零。回收前重新核实新旧文件名称、父目录、大小、指纹及所在范围。

符合时保留归档原版，直接将本批新视频副本移入 115 回收站，文件步骤显示“完全相同的新副本已入回收站”。不需要先让九项参数都完整或同分，缺发布组不会阻止已经确认的内容去重。保留原版的 STRM、Token、字幕、NFO 与插件图片，不为被回收的新视频生成另一个 STRM。

只有大小或九项质量参数相同，不能据此认定是同一内容。指纹缺失/不合法或不一致时，继续原有九项规则；如最终同分则待处理。不同集、合并集范围不一致或身份不确定，仍保留原版。待处理模式及原位置跳过模式行为不变。

字幕先处理、视频最后回收：明确绑定的新字幕会规范命名，补到保留原版旁，并下载到原 STRM 同目录。保留语言、简繁、forced 等后缀；IDX/SUB 按各自文件归并。原版已有同名且指纹和字节数一致的字幕时，先核实保留字幕与本地输出，再回收新字幕副本。原版已有同名但内容不同的字幕、关联有歧义、缺可靠字幕指纹、原版没有受管理的 STRM 位置、下载/本地冲突等情况，暂停核查，新视频不回收，不留下完成状态的孤立字幕。

字幕归并计划先持久化；本地字幕按下载内容的 SHA1/大小校验，已存在的不同本地文件不会覆盖。云端改名、移动后再次核实，新增字幕绑定及本地哈希登记到保留原版的管理记录，供后续补齐和洗版管理。所有字幕的云端与本地结果核实后才回收新视频。字幕改名/移动/回收、新视频回收中断后，按记录核查续作，避免重复操作。该批次有字幕输出时按原通知设置通知 Emby 一次。不删除源文件夹。

回收继续复用已落盘的修改意图、按文件 ID 的回收站正面证据和原父目录核查。响应丢失/重启后不盲目再发回收；原版消失、指纹变化或结果不明时停止核查。不会永久清空回收站。

## 兼容与部署

不改数据库结构，不清空数据。新建整理任务会保存此策略；此前已创建的任务保持旧快照，不在重启恢复中途改变淘汰行为。旧的待处理记录不会自动重跑，需要将测试副本移回待整理目录后新建任务。

等当前整理结束，解压到 `/path/to/StrimKeep-v0.4.2-deduplicate` 后执行：

```bash
cd '/path/to/StrimKeep-v0.4.2-deduplicate/StrimKeep' &&
bash update.sh '/path/to/StrimKeep-v0.1.0-phase1/StrimKeep'
```

沿用原管理员、115 登录、配置、Token、数据/STRM 挂载及 Emby 路径。构建继续复制预编译前端，NAS 不运行 npm。
