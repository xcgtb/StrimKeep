## 根因与修复

原文件 ID 为 `3546307877859755390`；回收站条目 id 为 `3546310263571482388`。回收站 id 是回收记录 ID，不是原文件 ID。旧代码混淆两者，即使名称、大小与原目录一致也无法确认。不是质量规则判错，也不能用后来其他工具定时清空回收站解释首次失败。

- 原文件 ID、回收记录 ID 分开保存。只有服务明确提供 file_id/fid 才当作原 ID。
- 新意图先保存回收站记录快照，按新出现的唯一记录、精确名称、字节数、原父目录、类型及可用服务端时间核实关联，再检查原 ID 不再存续、原目录无该 ID。读回延迟仅重试读取，不重发回收。
- 原 0.4.2 意图没有快照时，以意图时间、服务端删除时间窗口、原父目录及精确元数据唯一关联，支持原任务恢复。时间/目录缺失、歧义、账号变化、文件恢复/移动或输出变化仍停止；没有人工跳过或强制完成入口。
- 核实后立即保存关联证据；其他工具后来清空回收站，恢复任务复用证据并核实当前状态，不要求条目永久存在。尚未核实且证据已清除的意图不自动判为成功。
- 正确识别 count=0 且无 data 的实际空返回；兼容列表及严格分页字典形式，未知/不完整返回不当作空回收站。

## 空目录清理

正常批次完成文件处理后，从叶到根处理该批次涉及的空源子目录和淘汰旧版后的作品/季目录。回收前核实范围、名称、位置及完整空列表，使用单目录回收和 API 非强制警告；保存意图和确认结果，不递归删除、不永久清空。有任何字幕、NFO、图片或其他项目都保留。配置根、媒体库根、分类/地区根及本任务无关目录保留。

本地仅对旧输出清理后相关空目录调用 rmdir，保留插件文件。云端清理异常保留视频结果，批次显示部分完成及原因。补齐输出维持云端只读。不会全盘清理历史无关空目录。
