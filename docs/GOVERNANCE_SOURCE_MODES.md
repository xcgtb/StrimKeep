# StrimKeep：自产与上游 STRM 双轨治理

## 两种来源分别做什么

| 模式 | STRM 范围 | 删除依据 | 注意事项 |
| --- | --- | --- | --- |
| **自产 STRM · 来源身份治理** | StrimKeep `output_root` / `share_output_root` | 从已登记 STRM 验证内容签名、资产 ID、115 账号身份及源文件快照 | 自产个人库只有来源核实成功、授权有效且人工确认后才允许对原文件执行操作；自产分享免转存仅清 NAS 引用，绝不删除分享源文件 |
| **上游 STRM · 路径治理** | 原挂载 `/media/local` / `/media/share`（以部署实际映射为准） | 沿用现有路径映射、目录归属、计划快照与删除保护 | 个人库如果挂载了可写源目录，执行删除可能联动源视频；分享库按原清理策略处理 NAS STRM；**播放 URL 不代表源文件删除授权** |
| **兼容双源（高级）** | 上游根和自产根 | 对各自文件仍执行其原有路径/身份核验 | 仅用于旧安装过渡；会把两类 STRM 同时纳入一个七维对照计划，可能与“分轨治理”的预期不同。一般建议分开扫描。 |

三个模式都保留：**七维规则、完整度优先、扫描→预演→人工确认、日志与执行记录**。七维不会从 STRM 文件大小推断真实画质。自产整理阶段对 115 视频可继续使用独立的八维策略。

## 切换方法

1. 打开「双库治理」，在 **治理来源与安全边界** 选择「上游 STRM」或「自产 STRM」。
2. 核实下方分别显示的“个人 STRM / 分享 STRM”目录及挂载状态；自产源要先在「STRM 输出与播放」配置可写输出位置。
3. 点击「保存并切换治理来源」，确认后**重新扫描**。在保存选择前，扫描/预演/执行按钮不可继续使用。
4. 核对新计划中的作品、画质、缺集及保留侧，再进行预演；真实删除必须单独人工确认。设置保存不会触发删除。

## 升级兼容与安全边界

- 已保存旧开关 `governance_generated_enabled` 与 `governance_generated_only` 的安装，不会在升级时被强制改成另一种治理范围。未显式选择新模式时：旧开关关闭→上游；接入自产且非仅自产→兼容双源；仅自产→自产。
- 新模式 `governance_source_mode` 生效后，后台同步旧布尔字段以兼容片库索引、追更和统计。旧客户端如果主动修改旧开关，会恢复旧开关的治理语义。
- **切换来源或输出根将改变治理规则指纹**；旧计划不能跨来源执行。后台正在运行的治理扫描或清理时，禁止通过网盘设置 API 切换模式或根目录。
- 已选自产库如挂载缺失，扫描会拒绝继续；不会把目录看作空库并产生误删除计划。
- 后台会拒绝清理不属于当前启用来源的路径；自生成 STRM 不允许回退到上游的路径猜测删除。
- 多个库可以使用同一个 NAS 但两个输出根不能相互包含，且自产源不能与另一类原治理根重叠；迁移之前先核实 Docker bind mount。

## 不等于已经完成的验证

离线测试验证了路径隔离、规则指纹、HTTP 保存和拒绝越界删除；**没有对真实 NAS / 115 / Emby 执行源文件删除**。在实际媒体库上线前，必须在隔离的测试目录先跑一次扫描、预演、播放和入库验收。
