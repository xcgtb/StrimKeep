# 我的网盘 Studio · v1.4.6

## 版本与范围

本补丁以远端 `main` 的 `9d44b4d`（v1.4.4 源码树）为基线，累计包含 v1.4.5 的直接转存修改。源码、镜像构建与 NAS 运行容器是不同验收层：本地通过不代表真实 115、Emby 或 Telegram 已完成部署验收。

## 日常工作与配置分开

| 日常入口 | 职责 |
| --- | --- |
| 工作台 | 最近任务、需要处理项、最近引用、实际入库记录及处理链路配置检查 |
| 资源接收 | 分享链接转存、磁力和机器人接收 |
| 网盘文件 | 按需展开真实目录、查看文件 |
| 媒体库 | 本项目 STRM 生成、记录与输出配置 |
| 任务中心 | 进度、结果、停止及不明写入只读核实 |
| 设置 | 可搜索的账号、目录、识别命名、分类版本、自动化、STRM、Emby、反代、通知和频道目录 |

工作台指标明确范围：最近 50 条任务、最近最多 100 条引用及当前账号最近 100 条入库检查，不当作整库统计。任务列表包含所有账号；播放引用及入库确认按当前账号展示。请求失败显示未知，不填假数据；进入页面只读取记录，不扫描整个网盘。

桌面配置为左侧模块导航、右侧表单；手机按单列阅读顺序排列。全局导航只保留六个入口，细分配置在当前页查找。保留真实控件 ID、DOM 节点和事件，不克隆提交按钮，不因导航自动写入配置。输出配置不提交反代和通知字段，反代配置不提交输出字段。

## 从上游日志采用的逻辑

- 从父目录的明确 TMDB 标记继承作品身份，支持来源直接选在季目录内。逐文件明确 ID 和手动修正优先；目录身份矛盾不猜测，父目录预览后变化则停止对应项目。
- 父目录读取按批缓存。无明确父目录 ID 的文件继续原保守匹配，不根据标题相似度强行执行。
- 电影例：`走私 (2023) - 2160p.BluRay REMUX.DoVi P7.H.265.10-bit.23.976fps.TrueHD 7.1-WF.mkv`。
- 剧集例：`征途.2026.S01E01.第1集.2160p.SDR.H.265.10-bit.60fps.AAC 2.0.mkv`。集名来自已核实的 TMDB 季集响应；自定义模板、原名模式和关闭重命名仍按用户选择执行。
- Emby 更新合并最多 100 个有效待检查路径；单个路径的内容、配置 revision、映射、TMDB 和季集继续独立核验。失败后不标记已提交；每十轮检查可再提交未确认路径，不用全库刷新替代入库证据。
- 取消「转存待整理-任务号」附加层；只处理本次核实内容。已有旧目录不批量删除。清理来源空子目录仍是显式可选设置，不删除配置根目录或含残留文件的目录。

本次没有将整个处理引擎改造成新的目录级 STRM 后台队列；已有逐文件生成和持久延时任务继续使用。不能把 Emby 路径批量刷新描述为已实现全链路后台增量引擎。

## 8096、8097 与本项目端口

用户提供的上游界面显示：上游监听 `8097`，真实 Emby 为 `192.168.3.55:8096`。域名仍指向 8097 时，播放器连接的仍是上游入口；本项目不开独立 Emby 反代不意味着无法播放。

本项目生成的 STRM 内含签名播放入口，通常由本项目服务端口（示例 8321）解析。可用直链返回 302；必须携带 Cookie 的提供商响应使用受限流式代理。这个入口不依赖独立 Emby 反代开关。

独立反代是可选的另一层：示例监听 8322，后端来自规则设置里的 Emby 服务连接。若要改用它，播放器或公网转发应指向该监听端口，不应与已有上游同时占用 8097。仅“能播放”不能证明最终是哪一层返回 302，也不能证明所有客户端都在直连。
