# StrimKeep 数据存储

正式数据库是 `/data/state/strimkeep.db`，开启 WAL。配置、订阅、库内状态文档、缓存、计划、运行日志与清理结果统一写入 SQLite。

| 内容 | 保存方式与生命周期 |
| --- | --- |
| 配置、订阅、手动完整标记 | SQLite 文档/状态；持续保存 |
| 片库、入库、TMDB 缓存及媒体索引 | SQLite；按各自刷新策略更新 |
| 待执行治理计划 | 2 小时后不可执行；旧未执行计划保留 7 天 |
| 已执行计划与清理存档 | SQLite；长期保存 |
| 运行日志 | SQLite；约保留最近 10,000 条 |
| Telegram 去重、轮询 offset | SQLite；去重键有过期策略 |
| 旧 JSON/JSONL | 首次迁移读取，成功标记后不再覆盖新状态；不继续双写 |

源码包不带数据库或任何运行记录。重新部署时使用空数据目录即可从空记录开始；复用原目录会保留原记录。应用启动不自动清空记录。

`docs.version` 历史必填且无默认值的表结构会幂等兼容；已有未知额外列不删。配置保存失败会上报存储诊断，不能把失败当成正常写入。

存储诊断可在 Web 顶部运行状态和日志中心查看。磁盘空间审计脚本只读取文件元数据，不删除或修改数据：

```bash
docker compose exec -T strimkeep python - < dev/tools/storage_audit.py
```

正式镜像只内置健康检查脚本；其他诊断和验收脚本从源码通过 stdin 执行。

健康检查只请求 `/api/health`，代表 HTTP 存活，不代表远端 API 可用或所有缓存已更新。
