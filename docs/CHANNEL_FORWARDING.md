# 频道监控、万能转发与 TG 通知

基于 v1.5.21（658f3654c683802366b72e4f0e78ee6f50e7d703）的 v1.6.0 改进。完整源码已包含公开网页读取补丁和构建后的前端，无需先应用旧补丁包。

## 频道处理动作

| 动作 | 行为 | 所需配置 |
| --- | --- | --- |
| 接收转存到 115 | 按频道筛选，将支持的资源接收到指定目录 | 有效 115 授权、接收目录；整理使用独立自动化 |
| 生成分享 STRM | 提取 115 分享，复用分享库识别、选版与生成流程，不转存 | 有效 115 授权、分享库输出、TMDB、播放配置 |
| 万能转发 → self | 按命令头直接进入内置处理；/strm 生成分享 STRM，/receive 转存 | 与对应内置动作相同 |
| 万能转发 → @机器人 | 使用登录的 Telegram 用户会话发送「命令头 + 原文 + 隐藏链接」 | 用户会话、可访问的目标机器人；命令由对方定义 |

进入「115 频道监控 → 万能转发 → 添加转发规则」，默认命令 `/strm`、目标 `self`。填写频道并选择读取模式，保存、启用规则即可。外部机器人可填写例如 `/create_115share_strm`，实际命令需符合对方机器人要求。转发的是文本和媒体说明，不复制视频/图片二进制，也不伪造 Telegram 原生转发来源标记。超长消息明确失败，不截断资源链接。

“匹配消息后自动处理”关闭时只记录，不调用 115、不向外发送。已有频道规则默认继续执行转存。频道转存与影视整理保持独立，旧 organize 字段兼容接收，不控制频道后续整理。

公开网页模式不需要 TG 用户 API；它只能读取公开预览，存在分页/网页结构等限制。用户会话模式支持历史读取、私有频道读取（账号需有权限）和外部转发。机器人模式仅接收已加入并具有管理员权限的频道更新。

**时序**：首次历史条数仅在建立游标时使用；0 从当前最新位置开始。暂停、重启、修改筛选后继续游标，不重新回放。修改频道地址或读取模式会重建游标；不希望重新回补时先把首次历史设为 0。卡片显示最近成功、检查数量、失败次数、下次检查和游标，机器人实时接收没有轮询时间。

**规则测试**：先保存暂停的规则，使用「测试筛选」检查匹配原因及命令预览，不发送消息、不触发生成或转存。公开网页另有只读抓取测试，可检查文字和链接是否可见。

## 给自己的机器人发送资源

可将频道帖子转发给 StrimKeep Bot，在文字或图片说明前添加 `/strm`，也可回复该消息发送 `/strm`。只读取当前命令及其直接回复的原文/说明/隐藏链接。授权仍依据发送命令的用户与现有白名单，不能通过伪造转发来源绕过。

`/receive` 继续执行资源接收；`/strm`、`/sharestrm`、`/create_115share_strm` 仅接受 115 分享，进入免转存分享库。根目录超过 100 项仍需在 Web 分批选择，目录内总量继续遵守原分享库上限。

## 错误与回执

| 原因 | 提示及处理 |
| --- | --- |
| 4100010 | 115 分享已取消，请更换有效分享链接 |
| 4100026 | 分享不存在或已删除，不擅自认定为过期 |
| 服务端明确返回分享过期 | 重新获取分享链接 |
| 服务端明确返回提取码/访问码错误 | 检查访问密码 |
| 授权失效或需要验证 | 检查 Cookie；需要安全验证时到官方客户端处理 |
| 未识别错误码 | 保留数字错误码及通用提示，不猜测具体原因 |

错误分别记录为「准备与配置核验」「读取分享」「提交转存」「核验转存结果」「生成分享 STRM」「发送转发消息」。接收历史同时展示后续子任务的失败原因；日志只保存安全诊断字段，不记录原始提供方响应、Cookie 或分享密码。TG 分模块通知开关仍控制回执是否发送。

发送前保存持久步骤，收到消息 ID 才确认已发送；断线、超时或缺失回执保留待核实，不自动重发。用户会话撤销、账号凭据变化、规则暂停/修订、停止任务都会阻止后续提交。已经发出的消息无法撤回，发送回执不证明外部机器人已处理。暂停规则阻止尚未提交的新操作；已经产生的转存或分享 STRM 子任务需到任务中心单独停止。

转存返回后再核验失败，任务保持 uncertain，可使用原任务的只读核验功能；不重复发起转存。分享取消等明确拒绝属于 failed。

## TG 卡片

卡片按作品/季归并，仅统计已核验的输出。版本行显示分辨率、来源、动态范围和编码；文件名或已识别来源明确含 REMUX 时才标注 Remux，不从体积猜测。“简繁英字幕”等字幕描述不作为发布组，未知组省略。无效的 0000 年份省略。

汇总保留 STRM 数量、目录结果和非零异常/跳过/过滤/版本保留，去除零计数噪声。可选文件明细仍由原通知设置控制。保持「115 整理完成」「分享 STRM 已生成」等真实阶段名称，不能将生成完成冒充 Emby 已确认入库。

## 飞牛使用完整源码包

本包是源码，不是可直接导入 Docker 的镜像，也不会自动更新 GitHub 或当前容器。解压到临时目录，先核对 Git 工作区没有自己的未提交改动，再将包内 StrimKeep 目录覆盖到现有源码目录，保留原 `.git`、私有配置和运行数据。旧静态资源仅可按 `dev/obsolete-assets-after-v1.5.21.txt` 的明确清单删除；新构建不依赖它们。

查看 `git diff --stat` 和 `git status` 后，按 `dev/PUBLISHING.md` 提交、使用新的版本标签构建镜像；不要复用或覆盖 v1.5.21 标签。本次发布版本为 v1.6.0，标签必须指向本次发布提交。重新拉取所发布镜像并重建容器后，刷新网页再检查功能。仅覆盖源码不会改变正在运行的镜像。

部署验收先关闭自动处理，用真实频道只读预览，再用单条有效分享验证生成/播放及 Emby 回执；最后启用自动处理。外部机器人首次先用一条短消息验证目标命令和接收权限。

参考：[Telegram Bot FAQ](https://core.telegram.org/bots/faq#why-doesn-39t-my-bot-see-messages-from-other-bots)、[Telethon 发送接口](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.messages.MessageMethods.send_message)。外部转发使用用户会话，内置处理直接进入本地任务。
