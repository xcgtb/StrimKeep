# 文件命名和任务通知

## 命名

标准模式按以下顺序生成文件名，缺失的媒体字段跳过：

`片名.年份.季集.[tmdb-ID].分辨率.来源.动态范围.编码.帧率.位深.音频.声道-发布组.扩展名`

电影不添加季集，简洁模式不添加 TMDB 标记。例如：

`圣诞夜惊魂.1993.[tmdb-9479].2160p.UHD.BluRay.HDR10.H265.23.976fps.10bit.DTS.7.1-WF.mkv`

此例用于说明格式；实际只使用解析或探测到的信息，不补造声道、位深或发布组。模板中产生的空白也替换为点。`23.976fps` 和 `5.1` 等数值不拆改，字幕的 `.zh.srt` 等语言后缀继续保留。

视频、匹配字幕、STRM 与 NFO 使用相同文件名前缀。作品目录沿用 `片名 (年份) [tmdb-ID]` 和 `Season 01` 格式。保留原名、关闭重命名仍按原设置执行。本次升级不会批量改动已归档文件；新的整理预览使用新规则。

## 输出位置

生成记录显示的是实际写入时的容器路径。旧记录 `/media/local/...` 对应原上游挂载，并不对应新建的 `./strm/local`。

使用独立挂载 `./strm:/strm:rw` 时，在「STRM 生成 → 输出与播放地址」保存个人 `/strm/local`、分享 `/strm/share`。保存后重新进入页面核对。已转存并归档的媒体可在「扫描与生成」选择归档目录补生成，不需要重新转存、移动影片。旧输出文件保留，不自动迁移或清理。

Emby 需挂载同一宿主机目录，例如 `/vol1/1000/docker/StrimKeep/strm:/strimkeep-strm:ro`，媒体库中添加 `/strimkeep-strm/local` 和 `/strimkeep-strm/share`。

## 两种通知

机器人晨报属于治理通知。网盘任务通知有独立总开关，晨报发送成功不代表 STRM 任务通知已经开启。

在「Emby 反代与播放 → 任务通知」开启网盘任务通知总开关和 STRM 同步及生成通知，点击保存。需要逐项路径时再开启 STRM 文件明细。既有开关不会因升级自动打开。

入库海报另需在「Emby 入库连接」填写服务地址、API Key、实际 Emby 路径，开启连接及确认入库后的 TG 海报通知。当前挂载示例填写个人 `/strimkeep-strm/local`、分享 `/strimkeep-strm/share`。还需启用生成后请求 Emby 扫描，并让 Emby 的媒体库包含这些目录。

STRM 生成成功、Emby 接受扫描请求与 Emby 实际确认入库是不同进度。只有路径、TMDB、季集均通过核验才发入库海报；可查看实际入库确认记录。新开关影响后续事件，不自动重发历史通知。

## 验证范围

使用远端接口替身验证命名、SQLite 记录、本地实际文件生成、输出目录切换和通知条件；真实 Chromium 验证手机与桌面配置保存。未宣称已连接真实 115、飞牛、Emby 或向真实 Telegram 发送测试消息。
