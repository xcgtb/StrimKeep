## 使用顺序

1. 我的网盘连接115 Cookie，在整理页选归档与未识别目录，保存命名/分类/可选ffprobe设置。
2. 资源接收中选择分享转存、磁力、ed2k、可选秒传目录。TG总配置填写Bot Token、通知聊天和白名单，开启当前账号TG接收。
3. 频道需要历史时先填写 API ID/Hash 和国际手机号，点发送验证码，再输入Telegram收到的验证码；如提示两步验证，填密码后再次验证。也可验证导入已有Telethon StringSession。会话加密保存，页面不回显。断开为本机移除；需要撤销设备可在Telegram官方客户端管理会话。
4. 新建频道，选择“用户会话”，设首次读取最近N条、轮询秒数和115保存目录，启用保存。N=0从当前最新位置开始。当前Telegram用户必须有频道访问权限；不会自动加入私有频道。Bot模式只收新消息且须频道管理员，历史条数应为0。
5. 在影视整理的“接收目录→定时整理”读取目录，默认勾选已配置目录；可取消不需要的。设置上方自动整理Cron/时区，点“保存所选目录的定时整理”。来源不能相互嵌套，归档/未识别不能位于来源内。点“用作当前扫描来源”可先手动预览当前目录。保存同组会暂停此前未选中的接收整理规则，不更改手工创建的其他规则。
6. 直接发分享、磁力或ed2k给Bot：按Web目录接收。`/strm https://115.com/s/…?password=…`：直接识别并生成分享库STRM。分享根目录超过100项时用Web分批选择；递归上限沿用分享库限制。命令发送代表明确请求生成，不会额外要求点Web确认。
7. Emby反代与播放页新增“入库连接管理”：填写名称、URL（例如`http://emby:8096/emby`）、API Key及Emby容器所见个人/分享STRM根路径，开启联动并测试连接。这里是入库连接；原302监听端口仍在原反代设置，不为每个连接另起监听器。
8. 生成STRM后，在同页刷新实际入库确认记录。只在Emby查到匹配的真实项目时确认。首次扫描后暂未匹配继续等待；配置或路径变化时旧证据失效，新配置需重新同步登记或点“重新检查当前配置”。开启TG总通知、STRM细分通知与连接的确认通知后发送卡片。

## 状态与边界

- 首次历史条数只对新频道游标生效；更改筛选/条数不重放已处理历史。更换频道地址/读取模式重置游标；同一频道删除重建是新规则，会重新读取。编辑规则后此前尚未执行的旧版本消息会停止，需在历史查看原因。
- 频道读取失败保留游标，显示错误并延迟5分钟重试。读取与云写入分开，消息/游标同事务保存。重启保持队列与游标；登录验证码有效10分钟。
- 云下载暂缓规则不删除失败任务。115任务长期失败时先在115处理失败任务再等待下轮；任务路径缺失时保守暂缓，避免把部分文件移走。接收目录任务不会在下载请求刚接受时宣称下载或入库完成。
- 独立Emby配置只影响该账号的网盘入库，未配置时沿用原总览刷新链；不将原总览库配置覆盖成新连接。
- 查询匹配意味着Emby登记与刮削身份已核实，不代表客户端播放链已实测。扫描请求、STRM发布与确认入库分别记录。确认回执先落盘再发消息；发送超时/失败不重复发卡片，状态中保留通知结果。进程在回执后、发送前退出可能漏一条通知，不会伪造播放成功。
- 连接关闭、配置版本变化、资产路径/内容变化、资产被撤销时停止沿用旧确认。新连接不会自动遍历全部旧库；在STRM页重新同步或对已有记录重新检查。
- 115分享取消/失效时分享STRM停止解析；本批不实现自建分享后删除临时源，按用户要求最后实施。分享自动追更、来源失效修复、神医助手深度删除Webhook等仍未完成。
- 首次引入Telethon依赖，下一次镜像的依赖层会重装；后续未修改依赖时可复用缓存。依旧只由新版本标签触发双架构镜像构建，没有加入另一套构建工作流。
