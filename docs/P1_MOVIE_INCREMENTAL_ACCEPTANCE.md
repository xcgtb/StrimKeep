# P1 电影增量：实施和验收（未发布）

## 覆盖范围

- `Movie` 与 `Episode` 使用同一套近 24 小时入库游标；后续轮询只把变化的电影 **Emby Item ID** 交给片库缓存，首次完整时间窗对账读取全部近期电影 ID。
- 对每个变化的电影通过 Emby `GET /Items?Ids=<ID>` 精确查证身份、类型、数量、路径库别，不会重新遍历全部电影 / 分集。
- 新 Movie 自动加入片库映射。跨本地和分享库合并要求可信数字 TMDB ID 相同，片名和年份同时匹配。TMDB 不明时保留独立条目；不能依据目录唯一或相似片名直接合并。
- 增量缓存更新后同步电影总数、电影列表、探索身份索引。SSE 只发布电影 Item ID 和版本号（不包含路径、密钥），`/api/library/changes` 读取受影响电影；Safari 的 30 秒轮询仍然兜底。已经显示的电影卡片仅更新文字/标签，保留原海报 DOM 节点。
- 电影更新失败、Emby 忽略 `Ids`、返回数量异常、ID/Type 不匹配、身份冲突时，**保留旧正确缓存**，绝不把失败当作删除依据。
- 删除、重命名、移动旧资源的负面事实仍交给原有周期全量校准。所有 P1 变化仅影响信息展示，**七维治理、STRM/源文件删除规则不变**。

## 自动化验收

- Python 全量回归、电影新片与跨库、不同 TMDB 不合并、Emby 错误与超时保留、初次和二次增量游标。
- 前端回归：电影 SSE patch 保留海报 `<img>` 节点；已有剧集回归不受影响。
- SQLite 旧状态、HTTP 鉴权与 SSE、静态资源版本、GitHub 构建发布边界。

## 飞牛实际 Emby 现场验收（运行前需要用户操作）

1. 将本版测试补丁解压到 **独立** `/vol1/1000/git/StrimKeep-P0-P1-test`，绝不覆盖正式 Git 工作区。
2. `bash dev/checks/run_p1_nas_readonly.sh "$PWD"`：自动构建独立 P1 镜像；使用隔离 SQLite 和只读本地/分享挂载；选择 Emby 最新可验证的电影，测试新增、已有电影库别恢复、超时保护。无合格电影样本时显式失败，不冒称通过。
3. Safari 电影测试补丁覆盖 `p1-safari-kit`，**先停旧测试容器、再启动**：`bash p1-safari-kit/p1-safari-control.sh bump-movie` 在「仅本地 / 双库」间切换。iPhone Safari 不刷新页面观察影视探索状态、片库映射卡片与弹窗；图片保持不重载。
4. 30 分钟隔离 Web 内存观察，之后仅只读对照治理预览。不要在测试时执行清理或删除。
5. 所有现场验证通过后，再合并到正式 Git 工作区并推送 GitHub。正式 Docker `strimkeep:p0-smoke` 可以继续运行，后续部署另行验收。

**注意**：测试容器的峰值 RSS 不能替代十几万分集的正式负载；Safari 实机与 NAS Emby 测试必须由 NAS 实际执行后确认。
