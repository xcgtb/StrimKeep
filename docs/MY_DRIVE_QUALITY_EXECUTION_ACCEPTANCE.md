# 整理八维执行与杜比共存

日期：2026-10-15。基线：远端 main/v1.3.5 `8cf4523eb93c12653c747a0748c3cd00183a13be`。可达最高历史语义标签仍为 v1.12.11；实际本批发布基线为 v1.3.5，不重写旧标签。本批是后续源码改动，未推送、未打新标签、未构建/核实生产容器。

## 功能变化

| 之前 | 本批效果 |
| --- | --- |
| 整理八维只有比较建议 | 保留默认“仅预览”，可明确选择“按策略执行洗版” |
| 同批同名候选保留先出现的一项 | 执行模式按作品、季集和版本组选择本批最优，平局保留先出现项；较差来片保留来源原位 |
| 已有版本不会自动替换 | 本批胜出项必须优于同组所有已登记版本，新 STRM 完整发布后再核实删除旧源/旧引用 |
| 杜比/非杜比仅建议共存 | 新归档视频按“杜比 / 非杜比 / 动态范围未知”分目录；不同组不互相洗版 |
| 同名新旧视频无法同时归档 | 新版本改用其作品目录下的 `版本-文件ID` 子目录，保留自定义视频文件名 |
| 异常只看原任务结果 | 持久化每个旧引用的洗版进度；历史提供“核实并继续洗版” |

沿用原主题配色，不增加依赖，不修改 Docker/Compose、旧七维治理或挂载来源删除策略。使用已有 Cookie 删除、完整指纹和回执校验；不需要 OpenAPI AppID。

## 如何使用

1. 在“115 网盘配置”启用已有的“允许通过 Cookie 删除已绑定的本地库源文件”。这仅是实际替换旧源的前提，不改变分享库只清理 NAS 的规则。
2. 在影视整理启用八维比较，选择“按策略执行洗版”，按需调整维度、档位和发布组优先级。默认模式仍为仅预览，升级不会替用户启用删除。
3. 选择是否杜比/非杜比分组共存。执行模式将未知动态范围独立成组，不将未知当作非杜比。
4. 保存整理配置时会说明源删除效果，以及已启用的定时整理也会使用当前已保存策略。取消则不保存。
5. 识别预览列出来片去向、待替换旧文件名/源 ID、保留来片及原因、逐维比较依据。实际洗版须勾选生成 STRM，关闭时前后端都会拒绝替换。
6. 确认执行后查看整理历史。延时任务仍在历史中独立显示，旧版在新输出发布和核实前保留。

所有目录和视频模板继续生效。示例仅表示相对位置，实际名称由用户模板生成：

| 版本 | 示例相对目录 |
| --- | --- |
| 电影非杜比 | `电影/国产电影/片名 (年份) [tmdb-ID]/非杜比/片名.年份.2160p.mkv` |
| 剧集杜比 | `剧集/国产剧集/片名 (年份) [tmdb-ID]/Season 01/杜比/片名.年份.S01E01.mkv` |
| 未确认范围 | `作品目录/动态范围未知/视频名.mkv` |
| 同名冲突 | `作品目录/非杜比/版本-115文件ID/原模板视频名.mkv` |

NAS STRM 采用相同版本层级。仅新归档按此规则创建目录，不批量搬动已登记的旧 115 目录。后续同步保留已有引用的版本后缀，恢复预览模式也不会把两个版本合并到同一路径；老引用没有后缀时保持原布局。

## 选择和替换范围

- 按 movie/tv、TMDB ID、季、集区分作品；共存开启时增加动态范围组。同组八维比较逐项决定，真实源视频大小参与，STRM 文件大小不参与。
- 只替换当前账号、当前归档范围内已登记版本。未登记旧片、其他账号/范围的影片不根据名称猜测删除。
- 旧版本必须处于 active，账号 UID、文件 ID、父目录/祖先链、名称、大小、SHA1、本地 STRM 签名/内容和输出挂载身份须核实。新源必须有完整 SHA1，旧视频和关联文件也必须满足原 Cookie 删除校验。
- 任一同组旧版无法核实就保留来片原位。旧源或字幕仍被未选中播放引用使用时阻止替换。同作品有未完成的延时发布或待核实发布记录时阻止再次自动洗版。
- 同组旧版有更优或平局项时，来片原位保留，不删除较差来片。执行不会自动扫描并治理整个存量归档。
- 对比仍来自文件名解析或已启用的 ffprobe 实测字段，来源在预览中可见；不会把文件名解析伪装成实际媒体提取。

## 执行顺序

先核实本次新源和所列旧版本；在安全的新路径改名/归档新视频与明确关联文件，完整发布新 STRM 和已配置附属输出，核实新文件/输出/作品身份及原洗版策略，再按已登记旧 ID 删除旧视频及关联文件。旧源获得明确回执后，才清理原字节仍匹配的旧 STRM 和本工具附属文件，撤销旧引用。已变化或其他活动引用共享的附属文件保留。

本地新增 `cloud_upgrades` 表，按原任务/旧引用唯一登记新引用、旧身份、策略、进度和结果。状态包括 pending、deleting、remote_deleted、pruning、needs_review、done；与原 `cloud_deletions` 回执配合，不重发未知源删除。

新输出失败时不会删除旧源；新视频可能已归档，按历史记录核对后同步，不自动回滚云端移动。某个旧关联文件删除失败时会保留旧 STRM，新版本已经发布可用。Emby 扫描请求失败仍显示待处理。

执行中的停止请求在当前新旧版本组处理完成或进入待核实时停止下一视频。已有已完成归档的延时联动任务沿用上一批行为，停止整理不取消它们；需阻止待执行洗版时在历史取消对应排队任务，或将洗版模式改为预览。延时期间关闭执行/更改策略后不会继续删除旧源，新版可发布，旧版保留并待核对。

## 核实与恢复

原任务结束且有未完成记录时，在历史点击“核实并继续洗版”，确认后会重新核对新版本及原策略。已发送旧源仅核实回执，未知请求不会重发；未发送的成员在原明确身份下继续处理。没有证据、凭证/策略变化、新版本变化或本地挂载变化时继续保留并提示。

如果旧源已全部核实删除但 NAS 清理失败，恢复先重查旧源回执，再清理原登记字节，不再发送旧源删除。完成记录可重复核实，不重复云端删除。原任务的失败/不确定状态作为历史保留，洗版记录显示最新结果，不用“成功”掩盖原任务的其他错误。
