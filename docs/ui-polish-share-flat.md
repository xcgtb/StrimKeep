# UI 与分享库目录改进

## 源码身份

2026-10-16 基于已发布 `v1.4.8` 的源码 `aa5ee98ab9cf2b9b69fbeef49c0314d52583b5b0`，在 `frontend/ui-polish-share-flat` 分支继续修改。本次记录为未发布改动，不移动现有标签。按仓库规则查询，可达历史最高语义标签仍为 `v1.12.11`；最近实际发布的这套 Vue 前端为 `v1.4.8`。界面版本仍读取运行后端，不写入分支或提交号。没有验证用户 NAS 上镜像或运行容器的修订。

## 页面改进

- 保留浅蓝配色，统一文字、边框、间距与表单层级，降低装饰性卡片密度。
- 总览增加四个工作流入口，近期入库改为紧凑列表，服务状态与推荐分区更清楚。
- 资源页按业务分组，支持搜索与分类筛选，整张卡片进入已有工具。
- 整理页突出来源、预览、修正、归档四个步骤，并连接命名、分类、输出配置。
- 手机提供总览、探索、资源、任务和全部功能的底部导航。设置支持指定分区的链接。
- 原有业务工作区与操作确认仍在；只读页面不会自动提交写入。

## 分享库输出

此前默认路径形如 `share/分享-编号/电影/作品/影片.strm`，现在直接输出 `share/电影/作品/影片.strm`。电影、剧集和作品层级继续按用户命名与分类设置生成；不强制使用示例中的中文名称。

更新代码本身不会自动扫描、移动 NAS 文件。打开同一分享，重新预览并确认生成后，复用原资产编号、nonce 和签名播放地址，将已登记的旧文件迁移到新的分类路径。现有发布逻辑核验新输出后才清理已登记、内容仍一致的旧文件；本次补充清理空的旧来源目录。目录中存在手工文件或无法核验的内容时保留，不递归删除。已有分享无需删除重建。

不同来源命中已存在的同名 STRM 时，预览跳过并提示核对，保留原文件。执行时仍有原有所有权与冲突检查；没有通过扁平输出绕过版本保留规则。升级前保存的旧输出计划因布局版本变化停止，需重新预览。所有操作仍不转存、改名、移动或删除 115 分享源文件。

## 安装

完整源码包包含已编译的 `static/`。更新源码部署时替换项目代码及整个 `static/`；Docker 部署需从新源码重建镜像并更新容器。不要把源码包解压到媒体或运行数据目录。源码更新与用户正在运行的容器更新是两个步骤。

本地截图来自正式 Vite 构建的实际浏览器渲染，接口使用隔离测试数据及合成海报，不代表真实 NAS 的媒体数量或连接状态。
