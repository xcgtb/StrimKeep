# 1.5.11 前端累计修复：删除结果、双库治理和规则比例

基于 GitHub main `9dd95ed43f9570167fd54ac44020972277e03a13`（已发布 v1.5.11 的提交）修改。未采用此前的紧凑布局试做版。本修复随 v1.5.12 发布，不移动 v1.5.11 标签；未验证 NAS 当前容器版本。

## 行为

- 批量删除完成后显示「关闭结果」，点击后收起回执、退出多选并清空选择，可以继续选择其他作品。
- 删除执行中可「隐藏进度（删除继续）」，并随时重新展开；隐藏时保留任务轮询，任务结束后解除操作锁。
- 单片删除同样提供结果关闭入口。详情弹窗中的删除区域允许滚动，避免手机上的按钮超出可操作范围。
- 删除进度仅保留一条进度条，保留实际删除、保留及失败计数和核验明细。

- 双库治理的已执行或失败计划不再沿用执行前的待清理数量，显示「— / 待重新扫描核实」。旧明细折叠为「执行前扫描快照」，可查历史计划路径，不当作尚待执行的数据。
- 新扫描完成后展示实际剩余项，确认为空时显示 0；受保护项和豁免数量在已执行状态明确标记为上次扫描数据。
- 比例滑块使用独立轨道与滑块样式，排除普通输入框的内边距、边框干扰。100% 轨道填满且滑块抵达右端，仍以 0.5–1.0 的原始比例保存。

Python API、删除规则、源文件处理及镜像发布配置均未修改。关闭结果或隐藏进度均不会提交新删除请求。

## 截图中的日志

截图中的「媒体总览刷新失败 / LibraryScanError」属于后端目录扫描错误。此类错误会保留旧索引，具体原因需要日志中的目录路径和原始异常才能判断。本次修复的是扫描快照的前端展示和规则滑块，不代表该 NAS 目录扫描异常已解决。

## 使用

源码包根目录即仓库根目录，包含前端源代码及已构建的 `static/`。先备份本地未提交修改，再合入 Git 工作区；实际部署配置及运行数据应保留在部署目录。

如需生成新镜像，应为此修复创建新的版本日志和不可变标签，不能覆盖 v1.5.11。
