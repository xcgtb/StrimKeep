# v1.2.12：执行状态、统计与初始化修复

基线为 GitHub main 的回滚提交 `db66f56ed1b3ce05fa97aba5e9a22af0c8ee6f26`，其文件树与 v1.2.10 相同。按用户指定以 v1.2.12 发布，不移动历史标签。

## 变化与兼容性

| 场景 | 现在的行为 |
| --- | --- |
| 清理执行状态保存失败 | 在文件删除之前停止，显示状态未能保存；原文件和待执行计划保留 |
| 同一计划并发领取 | SQLite writer reservation 与完整计划快照比较后，只允许一个领取者提交执行状态；CLI 和 Web/Bot 共用原文件互斥 |
| 服务中断后计划仍为 executing | 拒绝直接重发执行，提示先核实片库再重新扫描；没有自动恢复删除 |
| 兼容 CLI 清理未传计划编号 | 自动生成并提交计划后按原规则执行；无待清理项不创建无用计划 |
| 根目录消失、变成文件、权限错误或扫描中挂载变化 | 扫描失败，不发布部分或零数量统计，保留此前已验证数据 |
| 合法空本地库或空分享库 | 完整读取成功时正常显示零；单库使用仍需挂载一个真实空分享目录 |
| 根目录挂载身份已经更换 | 自动统计提示待核实；确认挂载恢复后，手动刷新总览并完整扫描可建立新基线 |
| 手动刷新期间故障或重启 | 总览派生缓存重新生成，最后成功的分类和数量仍保存在 SQLite，成功扫描后再替换 |
| SQLite 迁移失败 / 调度启动失败 | 服务仍可显示登录和诊断；后台未就绪，业务接口返回 503，操作不提交 |
| Emby 暂时离线 | 就绪探针不探测 Emby；外部连接故障继续按原流程显示，不触发初始化失败 |

七维画质决策、规则默认值、STRM 匹配准则、本地源先删成功再删 STRM、分享库只清理 NAS 文件均保留。Python 3.11 生产基线和 requirements.txt 不变。SQLite 无新增 schema 或配置字段，旧配置/API 密钥不会重置；以前追加的额外表和列也不会被清除。暂停的网盘扩展未合入本版本。

## 就绪与诊断

- `/api/health` 继续作为原有存活接口，保持既有响应契约。
- `/api/ready` 为公开的轻量就绪探针，仅返回状态和初始化阶段；初始化成功 HTTP 200，未完成或失败 HTTP 503，不返回路径、异常明文或密钥。
- `/api/runtime/status` 保留鉴权，并追加 readiness 与 statistics 状态；页面顶部和状态弹层显示未就绪原因或统计待核实。
- 初始化失败时 `/api/login`、`/api/logout`、`/api/health`、`/api/ready`、`/api/runtime/status`、`/api/storage/status`、`/api/logs` 和日志下载继续可用。其他业务 API 暂停，包括可能触发后台写入的强制读取。
- 修复数据目录权限、空间或损坏的必需状态后重启服务，以实际初始化结果恢复。日志中的具体原因与探针阶段一起排查；Docker 标记 unhealthy 本身不会自动重启容器。

```bash

docker compose up -d --force-recreate strimkeep
docker compose logs --tail=80 strimkeep
```
