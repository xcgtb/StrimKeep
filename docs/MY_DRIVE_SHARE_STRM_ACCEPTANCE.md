## 之前、修改、效果

| 之前 | 修改 | 使用效果 |
| --- | --- | --- |
| 分享必须先接收到自己的网盘 | 增加独立分享来源登记、递归扫描、识别预览和生成任务 | 选别人的分享视频/目录，直接生成 NAS 分享库 STRM，不占自己网盘存储 |
| 播放只认识自己网盘文件 ID | 分享 ID、账号及分享内文件 ID 单独绑定 | 使用分享下载接口解析播放，绝不回退自己网盘同 ID 文件 |
| 一个 STRM 输出根目录 | 增加分享库输出根目录和 Emby 内分享路径映射 | 默认 `/media/share`；与 `/media/local` 分离，禁止相同/相互包含的目录 |
| 分享没有独立作品修正 | 资源接收页增加分享 TMDB 搜索、季集修正 | 复用已保存命名、分类、地区与过滤设置；识别不确定项提示修正 |
| ffprobe 只处理自己网盘 | 分享只读适配器与独立探测缓存命名空间 | 沿用可选 ffprobe、限时限量读取、失败跳过/明确回退策略 |
| 新分享预览/转存任务保存明文提取信息 | 新记录加密分享码/提取码，保留旧排队任务格式兼容 | STRM、生成任务结果与历史中不包含原分享链接/提取码 |

生成主链只调用分享读取/下载接口。不会转存、远端改名、建目录、移动、删除文件或取消分享，不需要 OpenAPI AppID。明确归属的同目录字幕经分享适配器下载，NFO/可选 TMDB 海报沿用现有配置。只勾选一个视频时，不扩大读取到未选择的同级字幕；需要字幕可勾选相关项或整个目录。

## 如何使用

1. 按原部署保留 `/media/share:rw` 挂载，确认路径存在；已按 README 部署的不需要改 Dockerfile/Compose/YML。若映射路径不同，在“Emby 反代与播放”保存“分享库 STRM 输出目录”。它应与规则设置中的分享库扫描根目录一致。
2. 保存播放器可访问的服务地址；若 Emby 容器中的分享库路径不同，可填写“Emby 内的分享库目录”，不与本地库映射重叠。Emby 添加分享库并沿用现有反代连接。
3. 在影视整理保存需要的命名模板、分类、地区、过滤及 ffprobe 开关；这些配置也用于分享库。分享生成不执行八维删除或来源空目录清理。
4. 打开“资源接收 · 分享转存”，输入 115 分享链接和提取码，预览并进入目录，勾选视频或目录。点击“免转存识别预览”。原“转存选中内容”仍保留为独立操作。
5. 查看每个视频的分享库路径。待修正作品在本页“修正分享作品”选择文件、类型、季集并搜索 TMDB，点选结果后重新预览。分享修正与自己网盘整理修正分别保存于当前页面状态。
6. 点击“确认生成分享 STRM”，确认数量和 NAS 输出根目录；任务进入“整理历史与任务”，生成后请求 Emby 扫描。刷新失败保留已生成引用并提示重试。可在视频边界停止任务，剩余内容重新预览生成。
7. STRM 生成在 `分享-来源标识/分类/作品/季/...strm`。来源标识不使用公开分享码；不同分享互不覆盖。同一分享再次生成复用登记引用及签名，已撤销引用不会自动重新启用。

## 播放与治理边界

- 播放从登记分享读取父目录，校验文件 ID、名称、父目录、大小和 SHA1，再请求分享下载 URL；如 URL 提供 SHA1/大小则继续校验。使用原签名播放入口、CDN 主机校验、UA 和有需要时的 Range 代理。
- 分享请求不复用已缓存播放 URL，每次解析先核实分享。取消、密码变化、失效或文件指纹变化会停止播放；不会因缓存或个人网盘同 ID 文件而继续解析。已经由播放器取得的 CDN 地址/已开始的播放不能由服务立即收回，实际过期由 115 决定。
- 分享凭据保存在原 SQLite 中的加密来源记录，依赖现有凭据密钥和数据备份。密码变化后须重新预览生成来更新来源版本；旧引用在重新生成前停止解析。新预览/转存任务也加密保存，已有明文历史/旧任务不进行批量改写。
- 分享只从分享库清理 NAS 引用；即使误放进本地治理入口，也拒绝源删除及删除回执操作，不回退挂载路径删除。自己网盘同步和八维预览/执行排除分享来源，原七维判断保持。
- 输出目录必须存在且不经过符号链接；预览后配置、账号凭据或挂载身份变化则停止。未登记同名文件保留，人工修改的内容不会被覆盖。分享内多版本生成同一文件名时先提示冲突，需修正命名或分次选择，不自动洗版。
- 单批最多选当前页 100 项，递归累计最多 2000 个文件及目录、20 层；单个目录完整读取最多 2000 项。超过限制请进入更具体的目录再建任务。分享缺少大小/SHA1 不生成；过滤项不生成，不移动到未识别目录。
- 分享生成目前为手动任务；独立 STRM 定时扫描仍处理自己网盘目录，本批没有分享自动订阅/新增集追踪，也不会自动清理失效分享文件。
