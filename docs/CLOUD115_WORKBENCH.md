# 115 Python 网盘工作台

此功能基于 StrimKeep v1.2.12 的 `d607fd978a7ce9f9b29398377d55f88a4a9f6a53` 开发。本次准备按 `v1.3.0` 发布；镜像需推送新标签并通过 GitHub Actions 后才可拉取，没有修改或移动任何已有版本标签。旧 v1.2.11 的实现、P2/P3 安装器及临时实验部署不包含在本次功能中。

## 用户能做什么

侧边栏新增「网盘工作台」，账号、文件、转存、整理、STRM、播放、任务在这个页面完成。

| 功能 | 行为与效果 |
| --- | --- |
| 登录 | 页面显示二维码，用户用 115 App 扫码并确认；保存已验证的 Cookie 账号，不要求填写 UID、文件编号或 AppID |
| 文件 | 浏览分页目录，通过按钮选择来源、转存和整理归档目录 |
| 转存 | 输入分享链接并预览，选择文件或文件夹；每次先接收进独立任务目录，再核实实际目标内容与目标 ID |
| 整理 | 预览 TMDB 识别结果和目标名称；在 115 中实际改名、移动，并同步关联字幕等同名附属文件；可接在转存后自动执行 |
| 修正 | 不唯一的作品保留；在页面搜索并选择 TMDB 作品，必要时填写季集号，再重新预览 |
| STRM | 生成绑定来源文件 ID 的稳定签名入口，同时生成 NFO，下载关联字幕；可选 TMDB 海报 |
| 302 | 播放时按当前 UA 取得临时直链；直链需要 Cookie 时由服务流式代理，不向播放器暴露账号 Cookie |
| Emby | 可选独立端口反代，默认 8322；原 Emby 地址可为 8096 或其他端口，管理端口仍为 8321 |
| 自动化 | 保存定时来源→归档任务，自动整理和生成 STRM；共用现有任务互斥，可选现有 Telegram 通知 |
| 恢复 | 重启后的在途写入留待核实；转存超时只能核实目标，禁止重新发送原请求 |

## 设置与首次使用

1. 沿用现有部署的 Web 账号密码、数据目录与媒体挂载。若使用无密码模式，网盘账号管理接口不开放。
2. 在「播放」页保存播放器实际可访问的 StrimKeep 地址，以及容器内真实存在的独立 STRM 输出目录。目录需先通过现有挂载提供；不存在时不自行创建假根目录。
3. 需要 Emby 反代时，填写 Emby 库内对应的 STRM 根目录，并启用一个空闲的监听端口。原 Emby 地址与密钥沿用已有服务连接配置。桥接网络需要映射该端口；现有 host 网络无需另改管理端口。
4. 在「账号」页扫码并确认；选中账号后浏览文件，通过按钮选转存、来源和归档目录。
5. 预览分享并转存；可以勾选转存后自动整理、生成 STRM，也可以先转存，再在文件页选择任务目录后单独整理。识别不唯一的内容不会自动移动。
6. 在「任务」页查看已完成、待核实、冲突与生成路径。Emby 刷新失败会提示，可检查连接后在「播放」页重新刷新。

不需要重新导出临时 Web 密码，也不需要另一套实验 Compose。源码中的公共 Compose 仍只引用已经发布的 `latest`；在 `v1.3.0` 镜像构建成功前，拉取现有 `latest` 不会得到这些新功能。

## 来源与删除边界

媒体身份是 `provider + account UID + target file ID`。分享中的源 ID 与用户账号内新生成的目标 ID 分开保存。重命名和移动后仍核验原目标 ID，不用文件名重新猜来源。已经确认的作品身份用于后续更新，不因重命名重新靠标题配对；同一 ID 的内容指纹变化时停下来核对。

本期没有调用 115 文件删除接口，也没有改变原七维治理、旧路径匹配和原清理顺序。新 STRM 可以由现有库扫描，但「按 ID 经官方接口删除源文件」尚未实现；旧库也不会被自动推定为已绑定 115 身份。后续治理需单独读取来源记录、核验账号和目标 ID，再设计并验证删除回执。

STRM 更新仅清理本项目记录拥有的本地文件：同一个账号、同一完整扫描范围、同一个输出根目录身份，连续两次完整扫描均不再出现来源 ID，且本地文件字节摘要仍与记录一致，才删除其本地引用和已记录的附属文件。目录不完整、挂载变化、手工修改或外部同名文件均保留。源文件移动出该扫描范围也会进入此本地清理流程；不会因此删除网盘文件。

撤销引用会停用播放入口，重新同步不会擅自重新启用。断开账号会停用关联引用与定时规则，不删除网盘内容。

## 存储与升级

- 原 SQLite 中增加 `cloud_*` 表，不替换旧表和配置，不复制出第二套业务数据库。
- 账号凭据加密保存；账号密钥与播放签名密钥位于原运行状态目录，权限为 0600。它们与数据库需一起备份，缺失时停止解密或签名，不静默生成替代密钥。
- STRM 中只有资源标识与播放签名，没有 Cookie。签名入口是可分享的播放凭据；撤销引用可立即停用。
- Python 3.12 是当前 `p115client` 的运行要求，Docker 与 CI 一起升级；运行依赖见 `requirements.txt` 和 `requirements-cloud115.lock`。
- 可选反代失败不会改变管理台密码。原 v1.2.12 就绪检查、历史 SQLite 兼容与诊断接口保留。

## 验收范围

自动验证使用真实 SDK 导入和实际 SDK 请求参数构造，但由隔离的模拟远端返回结果；同时使用真实 SQLite、临时文件和本地 HTTP 服务。覆盖扫码会话归属、取消后的晚到响应、加密与密钥缺失、单次领取、实际改名移动、部分转存拒绝继续、超时只读核实、附属文件、稳定 STRM、来源变化拒绝播放、当前 Emby 鉴权、MediaSourceId/用户隔离、Range 与 WebSocket 转发。

真实 115 账号的扫码与风控、分享目录完整接收的时序、CDN 域名/UA/客户端播放行为、Emby 各客户端、移动端视觉、Docker amd64/arm64 构建和 NAS 部署尚未实际验收。不能把模拟测试通过等同于这些已验证。

本期实现 Cookie 扫码登录。OpenAPI OAuth 授权、123/光鸭适配、从外部源自动搜索订阅、官方 ID 删除与旧库身份迁移属于后续工作。定时任务目前是已选目录的自动整理与生成，不是自动寻找分享资源。

闭源分发前还需处理 SDK 依赖包的许可冲突，见 [依赖记录](CLOUD115_DEPENDENCIES.md)。当前结果适合代码审查和账号联调，尚不能宣称完成真实端到端生产验收。
